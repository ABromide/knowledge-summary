路由与规划优化 ​

RouteLLM ​

论文 PDF

  • 问题：同一类请求交给不同能力、成本或时延的模型时，如何避免“一律使用最强模型”造成浪费，同时维持任务质量。
  • 方法：从原笔记的“路由”分组可推断，核心阅读线索是构建请求级路由器，依据输入难度与模型能力选择后端模型；具体训练信号和路由策略需以论文为准。
  • 价值：如果路由判断可靠，可在质量、费用和响应速度之间形成可控折中，并让多模型系统按任务动态分工。
  • 限制 / 核验点：重点核验路由器使用的监督数据、是否依赖成对偏好、面对分布外请求是否稳定，以及成本节省是否包含路由器自身开销。

MoMA ​

论文 PDF

  • 问题：单一模型或固定路由规则难以同时适配多类型任务，系统需要更细粒度地组织多个模型或 Agent 的协作。
  • 方法：原笔记只将其列在“路由”下；精读时应先检查论文是否通过多模型编排、动态选择或混合机制完成任务分派，不能仅凭缩写确定技术细节。
  • 价值：该方向可能把“选哪个模型”扩展为“如何组合多个模型”，为异构 Agent 系统的能力复用提供路径。
  • 限制 / 核验点：需核验 MoMA 的准确全称、路由粒度、是否允许多模型并行、训练与推理成本，以及收益究竟来自路由机制还是更大的总算力。

HIPLAN ​

论文 PDF

  • 问题：长链任务中，平铺式计划容易遗漏依赖关系，局部执行错误也可能破坏整体目标。
  • 方法：从原笔记的“planning 优化”分组和名称可将“分层计划”作为首要阅读假设：把高层目标拆为阶段或子目标，再生成可执行步骤；实际层级和重规划机制仍需原文确认。
  • 价值：分层表达有望降低长任务的规划复杂度，并让执行进度、失败位置和重规划边界更清晰。
  • 限制 / 核验点：核验层级由谁生成、何时重规划、错误能否跨层回传，以及在短任务上额外规划开销是否得不偿失。

Routine ​

论文 PDF

  • 问题：Agent 反复处理相似任务时，如果每次都从零规划，会重复消耗推理与工具试错成本。
  • 方法：从名称可优先关注其是否将成功轨迹提炼为可复用的 routine，并在新任务中检索、组合或修订；原笔记未提供机制细节。
  • 价值：可复用流程可能提升重复任务的一致性和效率，也为从一次性轨迹沉淀程序化经验提供接口。
  • 限制 / 核验点：需确认 routine 的表示形式、生成与淘汰机制、对任务变化的适应性，以及复用错误流程时是否存在放大偏差的风险。

LATS ​

论文 PDF

  • 问题：单条推理或行动轨迹一旦早期选错，Agent 往往缺少系统性的探索、回溯和经验更新能力。
  • 方法：精读时应重点核验其是否把语言模型推理与树搜索结合，以行动、环境反馈和自我评估指导候选分支扩展，再从搜索轨迹中选择后续动作。
  • 价值：相比一次性生成，搜索式决策能显式比较多条路径，并利用环境反馈纠正早期错误，适合需要试探和回溯的任务。
  • 限制 / 核验点：关注搜索分支数带来的推理成本、价值评估是否可靠、环境是否允许安全回滚，以及性能提升是否依赖大量采样。

反思与反馈强化学习 ​

UFO（Unary Feedback） ​

论文 PDF

  • 问题：许多偏好优化方法依赖成对比较，但真实 Agent 轨迹往往只能获得单条结果的通过、失败或标量反馈。
  • 方法：从链接中的“Unary Feedback”和原笔记的“reflect related RL”分组可优先考察：方法如何使用单样本反馈驱动反思或策略更新；具体目标函数必须回看论文。
  • 价值：若无需构造成对偏好，反馈采集可能更简单，也更贴近真实环境只返回单次执行结果的情形。
  • 限制 / 核验点：核验一元反馈的形式、噪声鲁棒性、是否需要额外评判模型、反思文本是否真正影响策略，以及与成对偏好基线的公平性。

学习、记忆、递归与系统调试 ​

Learn-by-interact：A Data-Centric Framework for Self-Adaptive Agents in Realistic Environments ​

记录日期：2026-01-18 · 论文页面

  • 问题：现实环境中的交互轨迹可能因模型误操作而偏离原指令，直接拿来训练会造成“指令—轨迹”错配；完整轨迹中的有用子轨迹也容易被浪费。
  • 方法：先让 LLM 与环境交互产生轨迹，再进行“反向构建”：依据实际轨迹总结或改写匹配的指令，并可从一个长轨迹拆出多个子轨迹及其对应指令，同时过滤不合理样本。
  • 价值：反向对齐提升了训练数据的一致性和轨迹利用率，使 Agent 能从真实交互结果中持续构造更高质量的数据，而不是只依赖预先编写的理想指令。
  • 限制 / 核验点：改写指令可能把原本的失败“合理化”，从而掩盖执行能力不足；需核验过滤标准、子轨迹切分质量、是否保留原目标失败标签，以及自适应提升是否在未见环境中成立。

“反向构建”是这篇论文的核心创新点之一：先让 LLM 生成交互轨迹，再利用 LLM 的总结或抽象能力，根据轨迹生成或修改对应指令。它的重要性体现在三个方面：

  • 解决指令和轨迹不匹配：实际交互中，LLM 可能犯错，导致轨迹与原始指令不符。论文示例中，LLM 原本想上传 Google Drive 中的文件，却误选了 GCS；反向构建会把指令修改为“Link CSV file in Google Cloud Storage to BigQuery”，使指令与实际轨迹匹配。
  • 最大化轨迹利用率：一个完整交互轨迹可能包含多个有意义的子轨迹，可以为每个子轨迹生成新指令，从而增加训练数据量。
  • 提高数据质量：反向构建可以过滤不合理或有偏差的轨迹，提高训练数据质量。

Agentic Memory：Learning Unified Long-Term and Short-Term Memory Management for Large Language Model Agents ​

记录日期：2026-01 · 论文 PDF

  • 问题：长任务既需要保留跨阶段的长期经验，也需要维护当前目标和上下文；分别设计长短期记忆容易产生割裂、冲突或重复。
  • 方法：从标题可确认论文关注“统一学习长期与短期记忆管理”，但原始笔记尚无摘要；精读时应追踪记忆的写入、检索、更新、遗忘是否由同一策略学习，以及训练信号从何而来。
  • 价值：统一管理有望减少手工规则，让 Agent 根据任务阶段决定记什么、何时取用，并在长期积累与即时推理之间建立协调机制。
  • 限制 / 核验点：需核验“统一”是共享模型、共享表示还是联合目标；同时检查记忆污染、隐私、存储增长、检索延迟、跨会话泛化及消融实验。

Recursive Language Models ​

记录日期：2025-12-31

  • 问题：超长 Prompt 难以一次性装入上下文并完成可靠推理，单次调用也缺少对复杂任务的进一步分解和复查。
  • 方法：构建 Python 外部运行环境，把超长 Prompt 放到外部环境中，由模型递归调用多个“自己的分身”处理子问题，再汇总结果，相当于对任务进行多轮、分治式处理。
  • 价值：外置上下文与递归分解可突破单次上下文处理的限制；原笔记将直观效果概括为“让 AI 再做一遍，效果直接好了一大截”。
  • 限制 / 核验点：不能把收益简单归因为重复执行；应核验递归终止条件、子任务划分和汇总误差、调用成本、并行一致性，以及与普通 Agent、长上下文模型和单纯重复采样的对照。

DOVER：Intervention-Driven Auto Debugging for LLM Multi-Agent Systems ​

记录日期：2025-12-10

  • 问题：LLM 多 Agent 系统的失败会沿消息与角色链路传播，仅观察最终答案很难定位哪个 Agent、哪次交互或哪类提示导致错误。
  • 方法：根据标题，“干预驱动自动调试”应是主线：通过对系统组件或中间状态施加受控干预，并比较结果变化来定位故障；原始笔记没有更多正文，具体干预对象、搜索策略和诊断输出均待原文确认。
  • 价值：干预式诊断有望从相关性观察推进到更接近因果定位，减少人工逐条检查多 Agent 日志的成本，并为后续修复提供更明确的责任边界。
  • 限制 / 核验点：重点核验干预是否可安全复现、是否需要访问内部 Prompt 或状态、组合故障下能否定位、调试调用开销，以及诊断准确率和修复成功率的评测方式。

DeepAgent：A General Reasoning Agent with Scalable Toolsets ​

记录日期：2025-10-24 · 论文页面 · 代码仓库

  • 问题：固定的“规划—调用—观察”流程无法按需发现新工具；长任务中交互历史持续膨胀，关键信息丢失和错误累积会同时恶化推理与执行。
  • 方法：系统结合三部分：按任务需求自主搜索工具并保持连续推理；由辅助模型把历史并行压缩为情景记忆、工作记忆和工具记忆；用 ToolPO 强化学习同时利用最终成功奖励与工具调用、记忆折叠等过程奖励，并以模拟工具辅助训练。
  • 价值：把工具发现、上下文压缩和工具使用训练放入同一套通用 Agent 能力中，既扩展可用工具规模，也让长程任务能保留全局进展、当前计划和工具经验。
  • 限制 / 核验点：工具描述相近或含糊时，搜索和选择可能失准；过程奖励可能把“正确流程”固化为单一路径。还需核验记忆折叠是否参与 ToolPO 训练、辅助模型与检索的额外成本、压缩信息损失，以及模拟工具到真实工具的迁移偏差。

现在很多智能 Agent 都要按固定流程运行，例如先规划、再调用工具、最后观察结果。此类流程步骤死板，不能临时寻找新工具；任务步骤和交互记录变长后，也容易遗失关键信息并累积错误。DeepAgent 用三个核心能力处理这些问题：

  1. 自主找工具 + 连贯思考：不预先固定全部可用工具，而是在解决任务时根据需要搜索合适工具。
  2. 记忆折叠：把历史交互和思考过程压缩为情景记忆、工作记忆、工具记忆，减少上下文占用并保留关键进展。
  3. ToolPO 训练：一方面用 AI 模拟真实工具功能，另一方面同时评价最终任务结果和每一步工具调用，让正确过程获得更精细的奖励。

启动记忆折叠后，参数为 θaux 的辅助大语言模型处理此前的完整交互历史 st，通过压缩函数 fcompress 并行生成三类结构化记忆：

(ME,MW,MT)=fcompress(st;θaux)
  • 情景记忆（ME）：作为任务的“全局日志”，记录关键事件、重要决策节点和子任务完成情况，帮助智能体把握长期任务结构与整体目标。
  • 工作记忆（MW）：作为“短期任务缓冲区”，存储当前子目标、遇到的障碍及近期计划，确保记忆折叠后推理过程连续。
  • 工具记忆（MT）：整合工具交互经验，包括工具名称、调用方式及效果，帮助智能体从历史经验中优化后续工具选择与使用策略。

ToolPO 的总奖励由任务成功奖励与动作级奖励组成：

Rsucc(τ)+Raction(τ)

其中，Raction(τ) 涵盖“正确工具调用”和“高效记忆折叠”。由此引出两项需要继续核验的思考：

  • 搜索工具存在效率与歧义问题：当工具描述不够清晰，或两个工具差异很小时，模型可能难以抉择。
  • 多步骤工具奖励可能隐含固定流程：需要确认奖励设计是否会把“达成目的的正确过程”收窄成唯一操作序列，以及训练与推理分离时，Memory 工具是否真正参与 ToolPO 训练。
