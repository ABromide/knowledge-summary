训练数据工程：从采集到持续供给 ​

大模型数据工程不是“把文本倒进对象存储”，而是把来源、质量、权限不同的数据，持续转换为可解释、可复现、可撤回、能稳定供给训练的数据产品。token 数只是结果；长期价值取决于来源证据、转换契约、质量实验和版本边界。

本章学习目标阅读前先建立清晰预期
建立端到端数据管线用实验而非直觉定义质量让训练输入可追溯、可恢复

本文聚焦文本与代码预训练数据，并延伸到后训练与多模态。所有阈值和过滤器都应在目标模型上验证，不能照抄公开配方。

一套可落地的数据产品验收框架

先把数据管线看成一个控制系统 ​

一条可运营的链路至少包含六层：源数据登记，原始对象落盘，解析与标准化，安全和质量过滤，去重与混合，分片后流式供给训练。旁路还要保存删除清单、抽样样本、阶段统计、规则版本和血缘。任一步骤发生改变，都应生成新版本而不是静默覆盖旧结果。

这套结构之所以重要，是因为“更多数据”与“更好的模型”之间没有单调关系。DataComp-LM 固定模型、训练代码和评测，把竞争对象限定为数据选择方案，说明数据工作需要像模型实验一样接受受控比较；FineWeb 对抓取快照、过滤与去重做消融，也展示了局部看似合理的规则可能损伤最终能力。

采集：先登记权利和语义，再下载内容 ​

采集任务的输入不应只有 URL 列表。每个数据源至少登记：源名称与稳定标识、抓取时间、作者或发布者、获取方式、许可及其证据、允许用途、地域和语言、内容时间范围、更新频率、删除机制、原始对象校验和。网页还要记录最终 URL、重定向链、响应头与抓取策略；代码仓库要保留仓库和提交标识，而不只是文件内容。

原始区采用只追加策略。抓到的 WARC、JSON、压缩包或仓库快照不原地修改，解析结果则写入新的派生层。这样既能重放管线，也能回答某条文本究竟来自哪个对象、经过了哪些规则。Datasheets for Datasets 建议记录数据集的动机、构成、采集过程、用途和限制；工程上应把这些问题变成清单和机器可读字段，而不是在发布前补一篇无法校验的说明。

采集应先设置域名级速率、重试与内容长度上限，再考虑并发。身份凭证与原始内容分离保存，日志禁止输出密钥和私人正文。对访问或许可不明确的来源，默认进入隔离区。

解析与标准化：保留信息，而不是制造“干净幻觉” ​

网页提取通常要去除导航、广告、脚本和重复页脚，但正文抽取器可能把代码块、表格、公式或引用关系一并丢掉。稳妥做法是同时保留原始对象、结构化表示和纯文本视图，并记录解析器名称、版本、置信度与异常标记。PDF、扫描件和 OCR 文本还应保留页码、版面坐标和 OCR 质量，便于后续定位错误。

Unicode 规范化、空白折叠、控制字符处理、编码修复与语言识别都要有明确顺序。标准化太晚，会让等价文本逃过去重；标准化太早，又可能把有语义差异的代码缩进、全角符号或组合字符合并。建议为自然语言、代码、数学和对话分别定义 schema，并用 content_type 驱动规则，而不是让一组正则处理所有数据。

每条记录需要稳定标识：来源主键支撑删除和更新，原始摘要识别内容变化，解析后的规范化摘要服务精确去重。对象存储路径会随重分片或迁移变化，不应充当身份。

去重：目标是控制记忆与分布，不是追求唯一率 ​

去重至少分为四类。URL 去重消除相同地址的重复抓取；精确去重按规范化内容摘要合并完全相同文档；近似去重用 MinHash、LSH 或 n-gram 重叠寻找模板化、转载和轻微改写；子串去重则识别一篇文档被另一篇大文档包含的情况。代码还要考虑 fork、vendor 目录和自动生成文件，跨语言数据要避免把短公共短语当作重复。

工程上最关键的并非算法名字，而是“聚类后保留谁”。可按来源可信度、解析完整度、发布时间、许可清晰度和质量分数选择代表文档，同时保留簇大小与成员表。超大重复簇往往是站点模板、免责声明、SEO 内容或跨快照重复，它们会让模型过度看到少量模式；但把所有近似项都删光，也会削弱合理重复所表达的真实频率。FineWeb 的消融说明，去重范围和顺序会影响下游结果，因此阈值必须在小模型上做对照，而不是只看“删掉了多少 token”。

训练集和评测集之间的污染要单独处理。先冻结评测集版本，对问题、答案、解释和常见改写生成匹配特征，再在文档级与窗口级扫描训练候选。命中后记录规则、重叠范围和处置结果，避免只删除一个完整字符串，却留下包含答案的相邻段落。去污染规则也不能使用未来才发布的评测集去改写历史数据版本，否则实验时间线会失真。

去重至少监控重复率、近似簇规模、各域删除比例、语言和时间分布变化、污染命中率。全局平均值会掩盖某个低资源域被模板规则整体清空的问题。

质量过滤：分层决策比单个“质量分”可靠 ​

第一层是确定性安全检查：无法解压、无法解码、正文为空、异常超长行、字符比例极端、恶意文件、明确个人敏感信息等。第二层是启发式信号，如文本长度、句子结构、符号比例、重复 n-gram、语言置信度、站点模板密度。第三层才是模型评分，用分类器或语言模型估计教育价值、可读性、主题与风险。每层都输出原因码，不只输出保留或删除。

模型过滤器会继承标注者和教师模型的偏好。FineWeb-Edu 用合成标注训练教育质量分类器并通过下游训练验证收益，这条路线的重点不是“LLM 评分天然更准”，而是先定义可审计的评分标准，再用小规模真实训练实验校准。对于方言、短问答、代码注释和专业符号，应建立分层抽样，检查误杀是否集中在特定群体。

质量评估需同时看静态数据指标与模型指标。静态指标包括 token 保留率、语言和域分布、长度分位数、困惑度分布、敏感信息命中与人工一致率；模型指标包括固定预算下的 loss、领域困惑度、下游任务、记忆和安全评测。只看分类器分数会形成自证循环，只看最终大模型又过于昂贵。更实用的是“规则单测—样本审阅—小模型消融—关键版本大模型复核”的阶梯。

删除数据时保存最少必要证据：记录 ID、阶段、规则版本、原因码和非敏感统计即可。把所有被删的敏感正文长期保存到统一旁路，会让过滤系统反过来成为高风险数据仓库。

数据混合：比例是一项模型超参数 ​

网页、书籍、论文、代码、数学与对话的 token 不能简单拼接后均匀抽样。体量最大的域会支配梯度，小而关键的域若完全按自然分布采样可能几乎不可见；反过来反复上采样小域，会提高记忆风险并造成过拟合。混合清单应写明每个域的候选 token、目标权重、温度、单样本最大重复次数和随训练阶段变化的计划。

DoReMi 使用代理模型和 group DRO 学习域权重，展示了以较小实验寻找大模型数据配比的思路。它不是自动配方：域定义、参考模型、代理容量和目标预算都会影响权重。生产中可把人工先验作为安全边界，把代理实验用于局部调整，再通过多个下游任务和最差域表现验收，避免平均指标上涨但关键域退化。

混合还包括时间策略。基础知识可以跨版本复用，新闻和代码则应有时间截点；后训练数据需要区分人工示范、合成数据、工具轨迹和线上反馈。合成数据必须记录生成模型、提示词版本、采样参数与验证器，防止多轮迭代后无法判断错误源头。线上反馈只有在用户授权、脱敏、去提示注入和质量确认后才可进入候选区。

分片与流式读取：训练看到的是字节流，不是数据湖概念 ​

训练消费层的目标，是让每个 rank 在需要时获得可解码、足够随机且不重复的 batch。常见格式包括 Parquet、Arrow 与 tar shard。分片不宜太小，否则元数据与打开请求放大；也不宜过大，否则重试、并行度和局部洗牌变差。每个 shard 应有记录数、token 数、字节数、校验和、schema、数据版本和域分布清单。

Hugging Face Datasets 的流式模式 使用 IterableDataset 边迭代边读取大数据集，适合无法整体下载的语料；但流式不等于天然随机。需要设计 shard 顺序随机、有限缓冲区洗牌、节点与 worker 分片，以及 epoch 或 token 预算边界。随机种子、world size、worker 数和数据游标共同决定样本序列，任一变化都可能破坏严格复现。

训练 checkpoint 不只保存模型与优化器，也要保存数据状态：数据版本、混合策略版本、当前 shard、shard 内偏移、随机数状态、已消费 token 和弹性扩缩容策略。失败恢复后若从 shard 开头重读，既浪费计算又改变样本频率；若直接跳到估算位置，又可能漏数据。数据加载器必须对“至少一次”还是“恰好一次”的语义做出明确选择。

输入管线可能成为 GPU 空转的根因。应监控取数等待时间、解压与 tokenization 时间、CPU 利用率、网络和存储吞吐、预取队列深度、坏 shard 率与 batch 生成延迟。对于图像、视频和音频，NVIDIA DALI 可把解码、裁剪等流水线组织为执行图并使用 GPU 加速；是否采用取决于 CPU 瓶颈、算子覆盖和端到端收益，而不是“预处理上 GPU”这一标签。

治理：让每个模型版本能回答“学过什么” ​

数据治理的最小单位是不可变版本与血缘边。版本清单关联原始来源、代码提交、规则配置、删除列表、混合权重、分片校验和、评测结果与审批人。模型清单再引用精确的数据版本和训练时间截点。这样收到删除请求、许可变化或污染报告时，才能判断影响了哪些派生数据和模型。

Data Provenance Initiative 对大量公开文本数据集的许可与归属进行审计，发现许可缺失和误分类普遍存在。这提醒我们：license 字段不是存在就可信，必须保留原始证据、判断依据、适用范围和冲突状态。混合数据集的整体许可也不能简单继承任意一个上游标签。

访问控制应按原始、隔离、派生、发布和删除证据分区；高风险字段单独加密并记录访问审计。删除链路要从来源主键找到所有派生记录、shard 和数据版本，生成可验证的 tombstone。对于已经训练的模型，还要记录处置决策和风险评估，不能声称删除训练文件就等于模型已遗忘。

治理演练：从来源撤回到模型影响分析 ​

假设一个长期采集的数据源通知许可证发生变化，并要求停止使用历史内容。收到通知后，首先冻结该来源的新采集任务，保存通知原文、时间、适用范围和处理工单，不能直接在存储桶里按域名模糊删除。治理服务应以来源主键查询原始对象，再沿血缘图找出解析记录、去重簇成员、混合版本和训练 shard。若同一正文也来自许可仍然有效的独立来源，需要由证据判断能否保留，不能因为内容摘要相同就把来源权利混为一谈。

第二步生成影响清单。清单至少分成“仅存在于候选区”“已进入发布数据集”“已被训练作业消费”三层，并列出对象数、token 数、语言和领域分布、涉及的数据版本、训练 run 与模型版本。对尚未训练的数据，可以创建 tombstone、重写受影响 shard 并发布补丁版本；重写后要重新计算校验和和混合比例，确保删除没有让某个领域意外失衡。旧版本进入禁止消费状态，但保留最少审计元数据，防止后来无法解释版本差异。

对已经消费过该数据的模型，文件删除并不等于参数遗忘。处置人需要根据内容敏感性、出现频率、重复簇规模、模型暴露范围和可提取性测试选择继续限制使用、重新训练或采用经过验证的遗忘方案。决策、测试证据和例外批准都要关联到模型卡。完成标准不是“删除脚本返回成功”，而是血缘查询不再返回可消费对象，新训练任务无法引用旧 manifest，目标模型的处置状态可被发布系统强制执行。

再考虑一个更隐蔽的事故：正文解析器升级后，整体 token 保留率只下降两个百分点，看似正常，但某种语言因标点规则被误判，保留量下降一半。对此不能只监控全局总量。每次规则发布都应以旧版本为对照，按语言、来源、内容类型、长度和质量分数分桶比较保留率，并固定一组金标文档检查结构完整性。任何分桶越过变更预算，发布自动进入隔离，直到负责人审阅差异样本。

修复解析器后也不应覆盖错误版本，而是从原始区重放产生新派生版本，复用同一输入清单比较差异。随后重新运行去重和混合，因为新增回来的文档会改变重复簇和域比例。先以少量 shard 做训练侧金丝雀，确认吞吐、解码错误和样本分布，再扩大重建范围。这类演练验证了三件事：原始数据能否重放，指标能否发现局部退化，血缘能否把一次规则变化准确映射到数据和模型。

治理机制还应定期做反向抽查：随机选择一个训练 batch，从 token 位置追到样本、shard、派生记录和原始来源；再随机选择一个来源，向下枚举所有派生数据与消费模型。前者验证可解释性，后者验证撤回能力。任一方向断链，都说明当前 manifest 只是文件列表，还没有形成真正的数据血缘。

一套可执行的验收表 ​

发布数据版本前，逐项确认：来源和许可证据完整；原始对象可重放且校验和一致；schema 与解析器版本冻结；各过滤阶段有原因码和分层抽样；去重保留策略与评测去污染已验证；混合权重有代理实验或业务依据；每个 shard 可独立校验；多节点读取无系统性重复和遗漏；checkpoint 能恢复数据游标；训练侧能看到输入等待与坏数据指标；删除请求可沿血缘定位；数据卡明确限制、偏差与不建议用途。

最终验收不是“管线成功跑完”，而是用固定预算训练一组可比较模型，并能解释性能变化来自哪些数据决策。数据 Infra 的成熟度，体现在失败时能否定位一条记录，迭代时能否比较两个版本，争议出现时能否给出来源证据，扩容后能否继续稳定供给。
