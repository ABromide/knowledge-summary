## Let It Flow: Agentic Crafting on Rock and Roll 【RL Sandbox】 {#rl-sandbox}

- **问题：** 高质量、可执行、带真实反馈的 Agent 轨迹稀缺；噪声轨迹直接用于强化学习，容易造成奖励失真和 Optimization Drift。
- **方法：** 合成通用工具数据和基于 GitHub PR/Issue 的编程任务，再通过任务构建、独立审查、轨迹采集、执行重放与人工抽检形成完整流水线。
- **证据/结论：** Agent 数据不能只判断文本是否“像答案”，还必须验证任务可解、测试有效、轨迹逻辑成立且执行结果通过；原始笔记未记录具体基准分数。
- **工程价值：** 可把任务规格、可复现容器、参考解、测试和轨迹都沉淀为显式制品，适合持续生产代码 Agent 与工具 Agent 的训练数据。
- **限制：** 合成数据会继承种子仓库、生成模型和 Judge 的偏差；容器构建、回放与人工抽检成本高，执行通过也不等于测试充分。

link：[https://arxiv\.org/pdf/2512\.24873](https://link.zhihu.com/?target=https%3A//arxiv.org/pdf/2512.24873)

数据合成策略： 由于开源的高质量 Agent 数据稀缺，团队采用合成策略：

1. 通用工具使用数据（General Tool-Use Data）：

- 基础工具调用：解析对话数据，映射为标准工具调用格式。

- 交互式场景：构建 Web 沙盒（如电商模拟器）和操作系统模拟器，生成需多步操作才能完成的任务。

2. 编程中心的数据（Programming-Centric Data）：采用多 Agent 工作流生成：

- Explore Agent：基于 GitHub 种子数据（PR、Issue），发散生成多样化的任务草稿。

- Instance Builder Agent：将草稿转化为可执行的 Docker 环境，自动推断构建和测试命令，确保持续集成通过。

- Review Agent：独立验证。运行参考解法确认可解性，并利用 LLM 审计测试用例的覆盖率和潜在的 False Positives。

- Trajectory Agent：在验证过的 Instance 上运行多种 Agent 框架（如 OpenHands, SWE\-Agent）收集轨迹。

多阶段过滤流水线： 为了防止噪声奖励导致 RL 策略崩溃（Optimization Drift），实施严格过滤：

1. 启发式过滤：剔除格式错误。

2. LLM\-based Judge：判断轨迹是否逻辑上解决了问题。

3. Execution Simulator：在沙盒中重放轨迹，验证是否通过测试。

4. Expert Inspection：人工抽检。

## 安全对齐的数据（Safety-Aligned Data） {#safety-aligned-data}

- **问题：** 只优化任务成功率的 Agent 可能执行代码注入、越界操作或欺骗性行为，工具权限越高，风险越大。
- **方法：** 将数据目标拆为 Safety & Security、Controllability、Trustworthiness，分别约束恶意操作、指令边界和行为可信度。
- **证据/结论：** 原始笔记给出的是覆盖框架而非量化实验；其结论是安全能力必须由专门数据显式训练，不能期待任务奖励自然产生安全行为。
- **工程价值：** 三类目标可共同用于红队样本分类、权限测试、训练奖励、行为审计和上线门禁。
- **限制：** 当前笔记未说明攻击面覆盖、误拒率和对抗评测；“可解释、无欺骗”等抽象目标还需要可执行的行为定义。

- Safety \& Security：防止代码注入、恶意操作。

- Controllability：确保严格遵循指令边界。

- Trustworthiness：确保行为可解释、无欺骗。



## Self-Distillation Enables Continual Learning {#self-distillation-continual-learning}

- **问题：** 基础模型持续学习新领域或新任务时，直接参数微调容易覆盖原有能力，产生灾难性遗忘。
- **方法：** SDFT 用带 Demonstration 的同一个模型充当教师，利用 ICL 生成指导信号，再对未看到 Demonstration 的学生做 On-Policy 自蒸馏；损失中屏蔽开头若干 Token 以缓解元语言泄漏。
- **证据/结论：** 消融显示 SDFT 对 ICL 能力弱的小模型无效；它要求基础模型已有相关潜能，只需由上下文示例激发。
- **工程价值：** 在没有外部强教师或难写奖励函数时，可用少量演示把模型自身的上下文能力固化为参数能力。
- **限制：** 对模型完全陌生的领域不适用；自蒸馏可能复制自身偏差，前缀 Mask 也不能保证消除错误知识或提示泄漏。

- 论文链接：https://arxiv\.org/pdf/2601\.19897

提出了一种名为 **SDFT（Self-Distillation Fine-Tuning）** 的方法，旨在解决基础模型（Foundation Models）在持续学习（Continual Learning）过程中面临的灾难性遗忘问题。

SDFT 利用模型自身的上下文学习（In\-Context Learning, ICL）能力，构建了一个以“演示（Demonstration）”为条件的教师模型，并通过在线（On\-Policy）蒸馏的方式指导学生模型（即原模型本身）。理论上，SDFT 可以被视为一种无需显式奖励函数的逆强化学习（Inverse RL）

<ZoomableImage src="/paper-reading/assets/截屏2026-02-03%2009.19.30.png" alt="截屏2026-02-03 09.19.30.png" />

> 由于 Teacher 是基于演示的，它可能会生成类似“根据以上文本\.\.\.”的元语言。SDFT 的学生虽然没有看到演示，但可能会通过蒸馏学会这些口癖。作者采用了一种简单的启发式方法：在计算 Loss 时 Mask 掉前几个 Token，有效缓解了此问题。
>
> 消融实验所示，SDFT 在小模型（弱 ICL 能力）上无效。它要求基础模型已经具备一定的能力，能够通过 Prompt 被“激发”。对于完全陌生的领域（模型无法通过 ICL 理解），SDFT 可能不如直接的参数更新有效。

## GDPO: Group Reward-Decoupled Normalization Policy Optimization 【2026-01-09】 {#gdpo}

- **问题：** 正确性、格式、长度和安全等异构奖励若先求和再归一化，会抹掉各维度信息，使全面优秀与整体平庸的样本产生近似训练信号。
- **方法：** 先对每个奖励分量独立做组内归一化，再聚合，最后做 Batch-wise 归一化；同时用条件奖励表达目标优先级并抑制 Reward Hacking。
- **证据/结论：** 原始笔记记录，GDPO 在工具调用、数学推理和代码生成上，正确率与约束满足度均一致优于 GRPO。
- **工程价值：** 适合同时约束答案质量、结构协议、成本和安全的生产模型，各奖励头还可独立监控与诊断。
- **限制：** 依赖奖励可靠拆分且尺度可比较；组内归一化对采样组构成敏感，奖励相关性和门控关系也可能产生新盲区。

- 论文链接：https://arxiv\.org/pdf/2601\.05242

- **GDPO（Group Reward-Decoupled Normalization Policy Optimization）**：该方法的核心在于**“先归一化，后聚合”**，即对每个独立的奖励分量分别进行组内归一化，然后再求和，最后辅以 Batch-wise 归一化来稳定数值范围。

- 实验表明，GDPO 在工具调用、数学推理和代码生成等任务上，无论是在正确率还是约束满足度上，均一致优于 GRPO。

在当前的后训练（Post\-training）阶段，强化学习（RL）需要模型同时满足多个异构目标，例如：

- **准确性（Correctness）：** 答案是否正确。

- **格式（Format）：** 是否遵循特定的 JSON 或 XML 结构。

- **长度（Length）：** 回答是否简洁，避免啰嗦。

- **安全性（Safety）：** 是否拒绝有害指令。

在多奖励 RL（Multi\-reward RL）的实践中，最直观的方法是将各个目标的奖励 R1、R2\.\.\.加权求和，得到总奖励 R\_sum，然后直接套用现有的 RL 算法。在多目标优化中，**先求和再归一化**的操作会造成严重的信息丢失。

<ZoomableImage src="/paper-reading/assets/image%2012.png" alt="image.png" />

<ZoomableImage src="/paper-reading/assets/截屏2026-01-12%2014.06.27.png" alt="截屏2026-01-12 14.06.27.png" />

模型无法区分“表现完美”和“表现平庸”，只要它们相对于组内最差样本的“相对差距”在统计学上分布一致。这种分辨率的降低直接导致了训练信号的模糊，使得模型难以快速收敛到同时满足所有最优目标的状态。

<ZoomableImage src="/paper-reading/assets/截屏2026-01-12%2014.08.13.png" alt="截屏2026-01-12 14.08.13.png" />

同时为了防止 Reward Hacking：采用条件奖励机制：**简单任务的奖励，只有在困难任务达成时才发放。**



## The Surprising Effectiveness of Negative Reinforcement in LLM Reasoning {#negative-reinforcement}

- **问题：** RLVR 中正、负样本信号的独立贡献不清楚；单纯追求 Pass@1 可能使输出分布过度锐化并损害推理时扩展。
- **方法：** 将训练拆成 PSR 与 NSR，分别做 Token 级梯度分析，并提出降低正样本权重的 Weighted-REINFORCE。
- **证据/结论：** 仅用 NSR 在 Pass@k 上可达到或超过 PPO、GRPO，尤其在较大 k 上更明显；加权方法在 MATH、AIME 2025、AMC23 上一致提升。
- **工程价值：** 对 Best-of-N、搜索和多路径推理，不应只强化唯一正确轨迹；保留替代路径可兼顾准确率与探索。
- **限制：** NSR 的优势集中在 Pass@k，不代表贪婪解码必然最优；它依赖可靠错误判定，也要求基础模型本来就包含合理候选。

- 论文链接：https://arxiv\.org/pdf/2506\.01347v2

核心结论如下：

1. **分解视角**：作者将 RLVR 的学习信号分解为正样本强化（PSR，即奖励正确答案）和负样本强化（NSR，即惩罚错误答案）。

2. **NSR 的有效性**：实验发现，仅使用负样本进行训练（NSR）就能在 Pass@k 指标上取得与 PPO 和 GRPO 相当甚至更好的效果，尤其是在 k 值较大时。这意味着模型在不被显式告知“什么是对的”的情况下，仅通过“什么是错的”就能显著提升推理能力。

3. **PSR 的局限性**：仅使用正样本训练（PSR）虽然能快速提升 Pass@1（贪婪解码准确率），但会导致模型输出分布坍缩，多样性下降，从而损害 inference\-time scaling（推理时扩展）的能力。

4. **梯度机制**：通过 Token 级别的梯度分析揭示，PSR 倾向于强化已生成的正确路径并抑制所有其他路径（包括潜在的正确路径），导致过拟合；而 NSR 通过抑制错误路径，利用模型自身的先验知识将概率质量重新分配给其他合理的候选者，从而保留了探索能力。

5. **Weighted\-REINFORCE**：基于上述发现，论文提出了一种加权 REINFORCE 算法，降低正样本的权重，在 MATH、AIME 2025 和 AMC23 等基准测试中取得了一致的性能提升。

<ZoomableImage src="/paper-reading/assets/image%2033.png" alt="image.png" />

**PSR 通过牺牲多样性换取了准确率（Exploitation），而 NSR 在提升准确率的同时保留了多样性（Exploration）。**

## Replay Failures as Successes: Hindsight Instruction Replay 【2026-01-04】 {#hindsight-instruction-replay}

- **问题：** 严格指令常同时包含多个约束，训练早期完整成功样本稀少，大量只满足部分约束的失败轨迹被浪费。
- **方法：** HiR 按多样性与约束完整性选择失败样本，随训练逐步提高完整性权重，再反向改写出响应能够满足的伪指令，将失败轨迹转成局部成功样本参与混合训练。
- **证据/结论：** “失败转成功”能为部分正确行为提供正反馈，早期重多样性、后期重完整性的调度提高样本利用率；笔记未保留具体性能数字。
- **工程价值：** 适用于格式、长度、语言、字段等可分解约束任务，可从线上失败中回收局部能力。
- **限制：** 伪指令可能偏离真实目标，局部成功与完整成功也不在同一比较空间；约束抽取、混合比例和重要性采样都会影响稳定性。

Code: https://github\.com/sastpg/HIR

论文提出的方法叫** HiR（Hindsight Instruction Replay，事后指令回放）**，思路很巧妙：

1. **挑有价值的 “失败样本”**：不是所有失败的回答都没用，模型训练初期先挑 “多样性高” 的失败回答（比如不同表达方式的错误），后期再慢慢侧重 “满足约束多” 的失败回答（比如只错了一个约束的），循序渐进不跑偏。

2. **给失败样本 “改指令”**：把原来的复杂指令，改成 “事后视角” 的简单指令 —— 比如原指令要求 “全大写 \+ 两段标序号”，某个回答只做到了 “全大写”，就把指令改成 “写两段评论，全大写字母”，这样这个 “失败回答” 就变成了 “满足新指令的成功回答”，给它发正向奖励。

3. **混合训练**：把原来的 “全对样本” 和改过后的 “失败转成功样本” 放在一起训练，模型既能学怎么全对，又能从部分正确的回答里学 “哪些约束能先满足”，不用死等 “全对的完美样本”。

<ZoomableImage src="/paper-reading/assets/image%204.png" alt="image.png" />

通过修改 instructions 将原来的 “失败回答” 变成了 “满足伪指令的成功回答”，模型能从里面拿到 “正向奖励”，知道 “这部分做得对”。

<ZoomableImage src="/paper-reading/assets/截屏2026-01-04%2009.27.33.png" alt="截屏2026-01-04 09.27.33.png" />

<ZoomableImage src="/paper-reading/assets/截屏2026-01-04%2009.45.03.png" alt="截屏2026-01-04 09.45.03.png" />

选择失败样本的评分函数：在 HiR 的“选择（Select）”阶段，为了从一组生成的失败响应里筛选出**有价值的失败样本**，论文使用了如下评分函数：

$$
F(y) = F_{\text{div}}(y) + \lambda \cdot F_{\text{int}}(y)
$$

$F_{\text{div}}(y)$ 衡量一个失败响应的**多样性**（基于 Token 级别熵）。

$F_{\text{int}}(y)$ 衡量这个响应**满足原始指令约束的程度（完整性）**。

$\lambda$ 是一个**权重系数**，用于平衡“探索多样性”与“约束完整性”之间的权衡（exploration vs. exploitation）。

公式 7 给出如下调度：

$$
\lambda = (1 + \eta)^s \lambda_0
$$

参数含义如下：权重 λ随训练步数以 **指数级** 上升，而不是线性增长：

- 当 $s$ 较小时，$(1 + \eta)^s$ 接近 1，约束完整性权重较小。

- 随着 $s$ 增大，$(1 + \eta)^s$ 指数增加，使得完整性得分的权重快速上升。

这种策略比线性增长更加**平滑且逐渐强化**重要性，有利于：

- 初期探索阶段强调多样性

- 中后期快速向重点约束学习转移

### 思考

1. 强化学习算法的选择：为什么不选择 GRPO

    **GRPO 依赖 “明确的偏好排序”，但 HiR 的 “失败转成功样本” 没法这么排**

    HiR 的核心是 “改写指令”：把原指令（比如 “全大写 \+ 标序号”）改成伪指令（比如 “全大写”），让原本 “部分满足” 的失败回答，变成伪指令下的 “成功回答”。这些改写后的样本有个特点：

    - 它们的 “成功” 是 “局部的”（只满足原指令的一部分约束），和原始的 “完全成功样本”（满足所有约束）不在一个 “评价维度” 上 —— 比如 “满足全大写” 的伪指令样本，和 “满足全大写 \+ 标序号” 的原始样本，没法说 “谁比谁更好”（因为对应的指令不一样）。而 GRPO 的核心逻辑是 “让模型学习‘A 比 B 好’的排序”，需要样本之间能明确比较。**如果用 GRPO，要么得强行给不同指令下的样本排序**（比如 “完全成功比局部成功好”），但这样会让模型忽略 “局部成功” 的价值（违背 HiR “利用失败经验” 的初衷）；要么得分开排序（原始样本一组、伪指令样本一组），但这样会把 HiR 的 “混合训练” 拆得支离破碎，样本效率大打折扣。

1. 伪指令的重要性的采样分母为什么还是原始指令？

    - 旧策略定义始终基于 **原始指令数据分布**

    论文的核心训练范式仍然是——**评估当前策略相对于旧策略（或行为策略）的改进**。旧策略是指令生成策略 $\pi_{\text{old}}$，这个策略定义了原始数据的行为分布：训练样本基于原始指令 $q$ 采样生成。

    即使使用伪指令 q’ 重新评价失败样本，它仍旧来自原始采样过程的行为数据。因此采用旧策略下的概率作为分母能保证 IS 仍然是在 **同一行为轨迹分布** 下进行校正，而不是在两个不同的条件分布之间随意改变权重基准。

    - 保持梯度估计的一致性与无偏估计（或低偏估计）

    重要性采样的目标是把 **old policy 分布下采样的数据** 重新加权为 **当前 policy 分布下的估计**。使用伪指令条件概率作为分母会改变行为分布基础，从而：

    - 引入统计偏差：因为原始采样轨迹是基于真实旧策略生成的，而不是基于伪指令策略；

    - 失去对旧策略与新策略概率差异的合理校准框架

    换句话说，如果分母使用伪指令概率，那 IS 估计的分布基础变了，**就不是对同一采样分布的 re-weighting 了**。重要性采样恒等式为：

    $$
    \mathbb{E}_{x \sim p}[f(x)]
    =
    \mathbb{E}_{x \sim q}\left[f(x)\frac{p(x)}{q(x)}\right]
    $$

    这里 q 是旧行为策略分布（原始指令下的旧策略）。伪指令不是旧分布的一部分，因此不能用作分母。



## Differential Smoothing Mitigates Sharpening and Improves LLM Reasoning 【2025-12-09】 {#differential-smoothing}

- **问题：** RL 微调会在正确轨迹内部继续坍缩到少数热门解法，丢失低概率但同样正确的路径。
- **方法：** 将成因拆成选择偏差和强化偏差，并以 Differential Smoothing 的分段奖励把熵用于正确轨迹，区别处理正确与错误分布。
- **证据/结论：** 两个命题表明高概率正确轨迹更易被采中且增益更大；错误轨迹呈相反趋势，因此统一熵处理会忽略正误轨迹的非对称性。
- **工程价值：** 应分别监控正确集和错误集内部熵，奖励塑形优先保护正确解法之间的覆盖度。
- **限制：** 原始笔记未完整记录分段奖励公式、超参数和基准增益；提高正确轨迹熵也可能保留低质量冗余路径。

### 核心算法：本质上是设计分段奖励函数，将熵用于正确轨迹

两大偏差驱动坍缩：RL 微调过程中存在两种偏差，共同导致了正确轨迹内部的多样性坍缩。

### 偏差一：选择偏差（Selection Bias）

选择偏差指的是，在基座模型（Base Model）下概率较高的正确轨迹，更容易被采样出来并获得奖励。

**命题 3\.1（Selection Bias）：**

对于任意两条正确轨迹 $\tau_1, \tau_2$，如果在基座模型下 $\pi_{\text{base}}(\tau_1) \ge \pi_{\text{base}}(\tau_2)$，那么 $\tau_1$ 相比 $\tau_2$ 更有可能在微调后的策略 $\pi_{\text{van}}$ 中获得概率提升：

$$
\pi_{\text{base}}(\tau_1) \ge \pi_{\text{base}}(\tau_2)
\Rightarrow
\mathbb{P}\!\left(\pi_{\text{van}}(\tau_1) > \pi_{\text{base}}(\tau_1)\right)
\ge
\mathbb{P}\!\left(\pi_{\text{van}}(\tau_2) > \pi_{\text{base}}(\tau_2)\right)
$$

这意味着，模型倾向于“发现”并奖励那些原本概率就高的解法，而忽略那些原本概率低但同样正确的解法。

### 偏差二：强化偏差（Reinforcement Bias）

强化偏差进一步指出，即使所有正确轨迹都被发现，原本概率较高的轨迹获得的提升幅度也更大。

**命题 3\.2（Reinforcement Bias）：**

对于任意正确轨迹 $\tau$，其概率增益的幅度直接正比于其在基座策略下的概率：

$$
\pi_{\text{van}}(\tau) - \pi_{\text{base}}(\tau)
\propto
\pi_{\text{base}}(\tau)
$$

这两个偏差共同作用，形成了一个“富者愈富”的反馈循环：高概率的正确路径被选中的概率大，且更新后的概率增幅也大。结果就是模型更显著地强化少数热门轨迹，导致分布锐化和多样性丧失。

值得注意的是，对于**错误轨迹**，情况恰恰相反：高概率的错误轨迹会受到更强的约束，导致其概率分布趋于平坦而非尖锐。

## Stabilizing Reinforcement Learning with LLMs: MiniRL 【2025-12-04】 {#minirl}

- **问题：** 训练与推理引擎的概率存在数值差异，长度归一化和不恰当的 Ratio 裁剪又可能破坏序列级奖励的一阶近似，导致训练偏差甚至崩溃。
- **方法：** MiniRL 以 REINFORCE 为基础，用组奖励作优势估计，引入训练—推理重要性采样校正，不做长度归一化，并用 PPO 风格掩码停止异常 Token 的梯度。
- **证据/结论：** 论文实践表明，忽略训练—推理 IS 校正会快速崩溃，加入长度归一化会得到次优性能。
- **工程价值：** 当推理采样和反向训练由不同引擎承担时，必须记录并校正两侧 LogProb，并把裁剪、长度处理和优势估计作为同一套目标验证。
- **限制：** IS 权重会受 LogProb 精度与策略陈旧性影响；不做长度归一化也会改变长短回答的贡献，笔记未给出完整跨任务公平对照。

https://www\.mlpod\.com/1294\.html

MiniRL 与 GRPO 和 CISPO 的主要区别在于它们在优化目标中处理训练\-推理差异、长度归一化和梯度裁剪的方式。下面我将分别说明它们的优化目标并总结它们之间的不同点。

**MiniRL 的优化目标**

MiniRL 是基于 REINFORCE 算法的，并进行了两个主要修改：奖励的组归一化作为优势估计，以及 PPO 中的裁剪机制来防止激进的策略更新。其优化目标可以表示为：

$$
\begin{aligned}
J_{\text{MiniRL}}(\theta)
= \mathbb{E}_{\substack{x \sim \mathcal{D},\\ y \sim \mu_{\theta_{\text{old}}}(\cdot \mid x)}}
\Bigg[
\sum_{t=1}^{|y|} M_t\,
\operatorname{sg}\!\left(
\frac{\pi_\theta(y_t \mid x, y_{<t})}
{\mu_{\theta_{\text{old}}}(y_t \mid x, y_{<t})}
\right)
\hat{A}(x,y)
\log \pi_\theta(y_t \mid x, y_{<t})
\Bigg].
\end{aligned}
$$

其中：

- $M_t$ 是一个掩码，根据令牌比率 $r_t$ 和优势 $\hat{A}(x,y)$ 决定是否裁剪。

- $r_t = \dfrac{\pi_\theta(y_t \mid x,y_{<t})}{\pi_{\theta_{\text{old}}}(y_t \mid x,y_{<t})}$ 是当前策略与旧策略的令牌似然比。

- $\operatorname{sg}(\cdot)$ 表示停止梯度操作。

- $\hat{A}(x,y) = R(x,y) - \mathbb{E}_{y' \sim \mu_{\theta_{\text{old}}}(\cdot \mid x)}[R(x,y')]$ 是组优势估计。

- $\dfrac{\pi_\theta(y_t \mid x,y_{<t})}{\mu_{\theta_{\text{old}}}(y_t \mid x,y_{<t})}$ 是用于校正训练—推理差异的重要性采样权重。



**GRPO 的优化目标**

GRPO（Shao et al., 2024）的目标如下：

$$
\begin{aligned}
J_{\text{GRPO}}(\theta)
= \mathbb{E}_{\substack{x \sim \mathcal{D},\\ \{y_i\}_{i=1}^{G} \sim \mu_{\theta_{\text{old}}}(\cdot \mid x)}}
\Bigg[
\frac{1}{G}\sum_{i=1}^{G}\frac{1}{|y_i|}\sum_{t=1}^{|y_i|}
\min\!\Big(
r_{i,t}(\theta)\hat{A}_{i,t},
\operatorname{clip}\!\left(r_{i,t}(\theta),1-\varepsilon_{\text{low}},1+\varepsilon_{\text{high}}\right)\hat{A}_{i,t}
\Big)
\Bigg].
\end{aligned}
$$

其中：

- $r_{i,t}(\theta) = \dfrac{\pi_\theta(y_{i,t} \mid x,y_{i,<t})}{\pi_{\theta_{\text{old}}}(y_{i,t} \mid x,y_{i,<t})}$ 是令牌似然比。

- $\hat{A}_{i,t} = \dfrac{R(x,y_i)-\operatorname{mean}(\{R(x,y_j)\}_{j=1}^{G})}{\operatorname{std}(\{R(x,y_j)\}_{j=1}^{G})}$ 是归一化奖励形成的优势估计。

- 注意，GRPO 的优化目标中包含了一个 PPO 风格的裁剪项。

- $\frac{1}{|y_i|}$ 表示长度归一化。



**CISPO 的优化目标**

CISPO（Chen et al., 2025）的目标如下：

$$
\begin{aligned}
J_{\text{CISPO}}(\theta)
= \mathbb{E}_{\substack{x \sim \mathcal{D},\\ \{y_i\}_{i=1}^{G} \sim \mu_{\theta_{\text{old}}}(\cdot \mid x)}}
\Bigg[
\frac{1}{\sum_{i=1}^{G}|y_i|}
\sum_{i=1}^{G}\sum_{t=1}^{|y_i|}
\operatorname{sg}\!\left(
\operatorname{clip}\!\left(r_{i,t}(\theta),1-\varepsilon_{\text{low}},1+\varepsilon_{\text{high}}\right)
\right)
\hat{A}_{i,t}
\log \pi_\theta(y_{i,t} \mid x,y_{i,<t})
\Bigg].
\end{aligned}
$$

其中：

- $r_{i,t}(\theta)$ 和 $\hat{A}_{i,t}$ 的定义与 GRPO 中相同。

- CISPO 也采用长度归一化因子 $\dfrac{1}{\sum_{i=1}^{G}|y_i|}$。

- 与 MiniRL 不同，CISPO 对令牌似然比进行裁剪，但不停止整个梯度；$\operatorname{sg}(\cdot)$ 仅应用于裁剪后的 Ratio。



**MiniRL 与其他算法的关键区别总结**

1. **训练\-推理差异的 IS 校正 （Training\-inference IS correction）**：

    - **MiniRL**：在其优化目标中明确包含 $\dfrac{\pi_\theta(y_t \mid x,y_{<t})}{\mu_{\theta_{\text{old}}}(y_t \mid x,y_{<t})}$，用于校正训练引擎和推理引擎之间的数值差异。论文指出，这是一个第一阶近似的内在组成部分，忽略它会导致训练迅速崩溃。

    - **GRPO 和 CISPO**：它们的原始目标中没有明确考虑训练\-推理差异的 IS 校正。



2. **长度归一化 （Length normalization）**：

    - **MiniRL**：不使用长度归一化。论文通过实验证明，添加长度归一化会导致次优性能，因为它会使第一阶近似失效，从而导致有偏的令牌级优化目标。

    - **GRPO 和 CISPO**：两者都在其优化目标中采用了长度归一化。



3. **梯度裁剪策略 （Gradient clipping strategy）**：

    - **MiniRL**：采用了 PPO 风格的裁剪机制，通过掩码 $M_t$ 停止某些令牌的梯度更新，以防止激进的策略更新并抑制策略陈旧性。

    - **GRPO**：也包含了一个 PPO 风格的裁剪项，但其形式与 MiniRL 略有不同，是将裁剪后的项与未裁剪的项取最小值。

    - **CISPO**：对令牌似然比进行裁剪，但没有像 MiniRL 那样停止某些令牌的梯度更新。论文指出，这种差异可能导致训练不稳定。



总而言之，MiniRL 的核心在于其优化目标与序列级奖励的第一阶近似保持一致，通过包含训练\-推理 IS 校正、避免长度归一化，以及实施有效的梯度裁剪来确保训练的稳定性和性能。而 GRPO 和 CISPO 则在这些方面有所不同，可能导致有偏的优化目标或训练不稳定。



## Titans: Learning to Memorize at Test Time 【Google Research, NeurIPS 2025】 {#titans-test-time-memory}

- **问题：** 有限窗口注意力难以持续保存长序列历史，单纯扩大上下文则带来显著计算和容量成本。
- **方法：** Titans 联合短时注意力、测试时在线更新的神经长时记忆 LMM 和持久记忆参数，并以 MAC、MAG、MAL 三种方式整合检索、写入、遗忘和任务知识。
- **证据/结论：** 原始笔记认为深层 MLP 记忆比线性记忆表达力更强且可分块并行；MAC/MAG 更充分利用短长记忆互补，MAL 更简单但可能受单层能力限制。
- **工程价值：** 为超长会话、持续 Agent 和流式数据提供参数内在线记忆路线，并明确不同记忆层的职责。
- **限制：** 测试时更新增加状态、计算与并发隔离难度；错误或恶意输入可能污染记忆，笔记未记录部署开销和基准数值。

https://www\.alphaxiv\.org/zh/overview/2501\.00663

### 1\. 核心思想：多层次记忆系统

Titans 架构的核心是模仿人类大脑的记忆系统，将记忆分为三个主要部分，它们各自扮演不同的角色并协同工作：

- **短时记忆（Short\-term Memory）：** 由注意力机制（特别是受限窗口注意力）实现。它负责捕捉当前上下文窗口内所有标记的直接依赖关系，提供高精度但范围有限的记忆。

- **长时记忆（Long\-term Memory，LMM）：** 这是 Titans 架构中最创新的部分，由一个专门的“神经长时记忆模块”构成。它能够学习记忆历史上下文，并随着时间推移不断适应和更新，从而保留长期信息。

- **持久记忆（Persistent Memory）：** 这是一组可学习但与输入无关的参数，用于存储任务相关的通用知识和抽象概念。它为模型提供了一个稳定的知识库。

### 2\. 神经长时记忆模块 （Long\-term Memory Module， LMM）

LMM 是 Titans 架构的关键创新点，它被设计为一个“元模型”，能够在测试时学习如何将数据记忆到其参数中。

- **设计原则：**

    - **在线学习：** LMM 的训练被视为一个在线学习问题，旨在将过去的输入信息压缩到其参数中。

    - **“惊喜”度量：** LMM 通过测量模型对输入的“惊喜”程度（基于梯度的变化）来决定记忆什么。一个“惊喜”的事件（与过去数据差异大的输入）更易被记忆。

        - 这种“惊喜”度量被进一步细分为**过去惊喜**和**瞬时惊喜**，并通过动量机制结合，类似于带有动量的梯度下降。这意味着 LMM 不仅关注当前输入的“惊喜”程度，还考虑了过去一系列“惊喜”的累积效应，从而更好地捕捉序列中的信息流。

    - **关联记忆损失：** LMM 的目标是学习键值（key-value）之间的关联，其损失函数为 $\lVert M_{t-1}(k_t)-v_t\rVert_2^2$。这意味着 LMM 在内部循环中优化其权重，以更好地将键映射到值，从而在测试时实现关联记忆。

    - **遗忘机制：** 为了有效管理记忆容量，LMM 引入了一个自适应的遗忘门 $\alpha_t \in [0, 1]$。这个门控机制可以根据需要选择性地遗忘旧信息，防止记忆溢出，类似于循环神经网络中的遗忘门。

- **架构细节：**

    - LMM 主要由一个或多个多层感知机（MLP）组成。论文认为深层 MLP 比简单的线性记忆模型更具表达能力，可以学习更复杂的非线性依赖关系。

    - **并行化训练：** LMM 的训练过程被设计成可以并行化，利用分块的梯度下降和结合矩阵乘法（matmul）运算，以充分利用硬件加速器（如 TPU、GPU）。

    - **卷积层：** 遵循现代线性循环模型的实践，LMM 在查询、键和值投影之后加入了 1D 深度可分离卷积层，以提高性能和计算效率。

    - **门控机制：** LMM 还使用了归一化和带有线性层的门控机制，以优化最终输出投影。

### 3\. 持久记忆模块 （Persistent Memory）

持久记忆是 Titans 架构中的另一个重要组成部分，它与输入数据无关，主要用于存储任务相关的长期知识。

- **组成：** 由一组可学习的参数 $P = \left[p_1, p_2, \dots, p_{N_p}\right]$ 组成，这些参数在训练过程中学习并保持固定，不随每个输入实例而变化。

- **作用：**

    - **任务知识存储：** 它存储了执行特定任务所需的抽象知识，类似于人类掌握技能的方式。

    - **前馈网络视角：** 从 Transformer 的角度看，持久记忆类似于数据无关的前馈网络权重，能够提供稳定的注意力加权。

    - **技术优势：** 在注意力机制中，由于因果掩码的存在，注意力权重通常对序列的初始标记高度活跃。将持久记忆参数添加到序列的开头，可以帮助重新分配注意力权重，从而减轻这种偏见并更有效地利用注意力。

### 4\. Titans 架构的整合方式

论文提出了三种不同的 Titans 变体，展示了如何将神经长时记忆模块有效整合到深度学习架构中：

#### 4\.1 记忆作为上下文 （Memory as a Context， MAC）

- **概念：** 将长时记忆视为当前信息的一个“上下文”。

<ZoomableImage src="/paper-reading/assets/截屏2025-12-08%2011.00.03.png" alt="截屏2025-12-08 11.00.03.png" />

- **工作流程（参见 Figure 2）：**

    1. **分段：** 将长序列 $x$ 分割成固定大小的段 $S^{(i)}$。

    2. **记忆检索：** 对于每个传入的段 $S^{(t)}$，使用其查询 $q_t = S^{(t)}W_Q$ 作为输入，从前一个时刻的长时记忆状态 $M_{t-1}$ 中检索相应的历史信息 $h_t = M^*_{t-1}(q_t)$（不更新 $M_{t-1}$ 的权重）。

    3. **上下文拼接：** 将持久记忆参数、检索到的历史信息 $h_t$ 和当前段 $S^{(t)}$ 拼接起来，形成新的输入序列 $\tilde{S}^{(t)} = \left[p_1, \dots, p_{N_p}\right] \Vert h_t \Vert S^{(t)}$。

    4. **注意力处理：** 对 $\tilde{S}^{(t)}$ 应用注意力机制，生成输出 $y_t = \text{Attn}(\tilde{S}^{(t)})$。注意力机制在这里决定了给定当前数据，长时记忆信息是否必要。

    5. **记忆更新：** 使用注意力机制的输出 $y_t$ 来更新长时记忆模块，即 $M_t = M_{t-1}(y_t)$（通过前向传播更新 $M_{t-1}$ 的权重）。

    6. **最终输出：** 最终输出 $o_t = y_t \otimes M^*_t(y_t)$。

- **优势：** 这种设计允许注意力模块在处理当前上下文时，能够根据需要利用历史信息，并指导长时记忆只存储有用的信息，从而更好地管理记忆容量。在测试时，持久记忆固定，注意力模块进行上下文学习，而长时记忆模块则持续学习和记忆信息。

#### 4\.2 记忆作为门 （Memory as a Gate， MAG）

- **概念：** 通过门控机制结合滑动窗口注意力（短时记忆）和神经记忆模块（长时记忆）。

<ZoomableImage src="/paper-reading/assets/截屏2025-12-08%2011.00.49.png" alt="截屏2025-12-08 11.00.49.png" />

- **工作流程（参见 Figure 4）：**

    1. **输入处理：** 将持久记忆参数拼接在原始输入序列 $x$ 前，形成 $\tilde{x} = \left[p_1, \dots, p_{N_p}\right] \Vert x$。

    2. **滑动窗口注意力：** 对 $\tilde{x}$ 应用滑动窗口注意力 （SW\-Attn），生成输出 $y = \text{SW-Attn}^*(\tilde{x})$。滑动窗口注意力作为精确的短时记忆。

    3. **神经记忆处理：** 对 $\tilde{x}$ 应用神经长时记忆模块，生成输出 $M(\tilde{x})$。神经记忆模块作为模型的渐逝记忆。

    4. **门控结合：** 将 $y$ 和 $M(\tilde{x})$ 的输出通过非线性门控机制 $\otimes$ 进行结合，生成最终输出 $o = y \otimes M(\tilde{x})$。

- **优势：** 这种设计通过多头架构将短时记忆和长时记忆并行处理，并利用门控机制灵活地平衡两者的贡献。

#### 4\.3 记忆作为层 （Memory as a Layer， MAL）

- **概念：** 将神经记忆模块作为一个层堆叠在深度神经网络中，通常在注意力模块之前。

- **工作流程（参见 Figure 5）：**

    1. **输入处理：** 将持久记忆参数拼接在原始输入序列 $x$ 前，形成 $\tilde{x} = \left[p_1, \dots, p_{N_p}\right] \Vert x$。

    2. **神经记忆层：** 首先通过神经长时记忆模块 $M(\tilde{x})$ 处理输入，生成输出 $y = M(\tilde{x})$。这一层负责压缩过去和当前上下文。

    3. **滑动窗口注意力层：** 接着，将 $y$ 作为输入，应用滑动窗口注意力 （SW\-Attn） 生成最终输出 $o = \text{SW-Attn}(y)$。

- **优势：** 这种更传统的串联组合方式易于实现，但在性能上可能会受到单个层能力的限制，不如 MAC 和 MAG 能充分利用记忆模块和注意力模块的互补性。

### 总结

Titans 架构通过精心设计的神经长时记忆模块和多层次的记忆整合策略，克服了传统 Transformer 在长上下文建模上的挑战。LMM 能够在测试时通过“惊喜”度量和遗忘机制自适应地学习和记忆信息，而持久记忆则提供了稳定的任务知识。MAC、MAG 和 MAL 这三种变体展示了将这些记忆模块有效融合到深度学习架构中的不同方式，为解决复杂、长序列任务提供了强大的新工具。

## Importance-Aware Data Selection for Efficient LLM Instruction Tuning {#importance-aware-data-selection}

- **问题：** 全量指令微调代价高，且大量样本对当前模型已无新增价值，需要不依赖外部教师的模型特定选择指标。
- **方法：** 对同一指令计算 Zero-shot 基础 Loss 与 One-shot ICL Loss，以两者差值构造 MIWV，动态定位示例扰动后暴露出的知识弱点。

- **限制：** MIWV 对示例选择、Loss 校准和差值方向敏感；Loss 变差也可能来自提示冲突或噪声，而非可学习的能力缺口。

## Black-Box On-Policy Distillation of Large Language Models {#black-box-on-policy-distillation}

- **问题：** 黑箱教师只返回文本而不提供 Token LogProb，传统 On-Policy 蒸馏难以对学生自己的状态给出稠密反馈，纯离线模仿又会产生分布偏移。
- **方法：** GAD 用学生作生成器、同架构模型加线性头作判别器；先做 SFT 与判别器热身，再让学生在线生成，由 Bradley–Terry 判别器打分并作为 GRPO 奖励，二者交替更新。
- **证据/结论：** 共同进化的判别器会随学生提升而提高标准，可在黑箱条件下形成 On-Policy 反馈并降低固定奖励被利用的风险；笔记未保留具体基准增益。
- **工程价值：** 适合从闭源 API 教师蒸馏到可部署小模型，只需缓存提示和教师回答，不要求访问教师参数或 LogProb。
- **限制：** 教师生成、学生采样和双模型训练成本高，对抗训练可能不稳定；判别器也可能只学到教师风格，而非事实与推理质量。

- **主要创新点**

    - **提出了 GAD （Generative Adversarial Distillation） 框架**：这是一个全新的、为黑箱大模型蒸馏设计的生成对抗式框架。

    - **实现了黑箱场景下的在线策略蒸馏**：通过 GAD，学生模型可以从自己生成的响应中学习，并获得有效的反馈，解决了黑箱蒸「在线策略」学习的核心难题。

    - **引入了一个与学生共同进化的“在线策略奖励模型”**：论文中的判别器（Discriminator）不仅仅是一个固定的裁判，它会随着学生模型的进步而变得越来越“严格”，提供动态和稳定的反馈，有效避免了传统强化学习中常见的“奖励作弊”（Reward Hacking）问题。

- **关键技术或方法**

    - **生成对抗网络 （GAN） 的思想**：将蒸馏问题重新定义为一个“猫鼠游戏”。学生模型是“生成器”（Generator），任务是生成尽可能逼近老师水平的答案。同时引入一个“判别器”（Discriminator），任务是区分答案究竟是来自老师还是学生。

    - **强化学习 （RL） 的范式**：将判别器的打分巧妙地用作奖励信号（Reward Signal）。学生模型的目标就是通过强化学习（具体用了策略梯度 Policy Gradient 算法）来最大化这个奖励，也就是生成能“骗过”判别器的答案。

    - **Bradley-Terry 偏好模型**：用这个模型训练判别器。对同一提示 $p$，教师回答 $y^{T}$ 的得分应高于学生回答 $y^{S}$。成对偏好概率为：

      $$
      P_D\!\left(y^{T} \succ y^{S} \mid p\right)
      =
      \sigma\!\left(D(p,y^{T})-D(p,y^{S})\right)
      $$

### GAD 训练流程

#### 第 0 步：数据准备

- **输入**：一个包含大量多样化指令（或问题）的提示集 $P$。

- **处理**：遍历每个提示 $p \in P$，通过 API 调用教师模型，获得回答 $y^{T}$。

- **输出**：蒸馏数据集 $\mathcal{T}=\{(p,y^{T})\mid p\in P\}$，它是后续训练的基础。

#### 第 1 步：模型初始化

- **学生模型（生成器 $G$）**：加载预训练好的学生模型权重。

- **判别器模型 $D$**：架构与学生模型 $G$ 完全相同。可以复制 $G$ 的权重初始化 $D$，再在顶部添加线性头，把最终隐状态映射为标量分数。

#### 第 2 步：热身阶段 （Warmup Stage）

此阶段进行一个 epoch，目的是让学生和判别器在一开始就达到一个比较“和谐”的水平。

- **输入**：蒸馏数据集 $\mathcal{T}$。

- **处理（并行进行）**：**训练生成器 $G$**——用 $(p,y^{T})$ 做标准 SFT，让 $G$ 在提示 $p$ 下生成教师回答 $y^{T}$。**训练判别器 $D$**——让当前 $G$ 生成学生回答 $y^{S}$，再用偏好对 $(p,y^{T},y^{S})$ 训练 $D$，使 $D(p,y^{T})>D(p,y^{S})$。

- **输出**：初步微调的学生模型 $G'$ 和具备初始辨别能力的判别器 $D'$。

#### 第 3 步：GAD 对抗训练阶段 （GAD Training Stage）

此阶段进行两个 Epoch，学生和判别器通过多轮交替更新共同进化。对于每个训练批次 $\mathcal{B}\subset\mathcal{T}$：

- **第 3.1 步：学生在线生成（On-Policy Generation）：输入**——一批提示 $p\in\mathcal{B}$ 和当前学生模型 $G$。**处理**——从 $G(\cdot\mid p)$ 采样回答 $y^{S}$。**输出**——一批学生回答。

- **第 3.2 步：判别器打分（Reward Calculation）：输入**——教师回答 $y^{T}$、学生回答 $y^{S}$ 和当前判别器 $D$。**处理**——分别计算 $D(p,y^{T})$ 与 $D(p,y^{S})$。**输出**——学生回答的奖励 $r_D=D(p,y^{S})$。

- **第 3.3 步：学生模型更新（Generator Update via RL）：输入**——学生回答 $y^{S}$ 及奖励 $r_D$。**处理**——以 $r_D$ 为奖励，使用 GRPO 更新 $G$，提高高分回答的生成概率。**输出**——更新后的 $G_{\text{new}}$。

- **第 3.4 步：判别器模型更新（Discriminator Update）：输入**——教师回答 $y^{T}$ 与最新学生回答 $y^{S}$。**处理**——用 $(p,y^{T},y^{S})$ 更新 $D$，进一步拉大两者分数差。**输出**——更新后的 $D_{\text{new}}$。

不断重复 3\.1 到 3\.4 步，直到训练收敛。

#### 第 4 步：最终输出

- **输入**：经过完整 GAD 训练的学生模型 $G$。

- **处理**：在评估集上选择表现最好的模型检查点。

- **输出**：一个能力大幅提升、学到了老师精髓的、可部署的最终学生模型。





## Retaining by Doing: The Role of On-Policy Data in Mitigating Forgetting {#retaining-by-doing}

- **问题：** 后训练既要提升下游能力又要保持预训练通用能力，而 Off-Policy SFT 对外部专家轨迹的强制拟合容易引发分布平移和灾难性遗忘。
- **方法：** 将 SFT 的 Behavior Cloning 与 PPO/GRPO 类 RL 对照：RL 从当前策略自行采样，在自身能力分布内筛选高奖励路径，并以 KL Penalty 与 Trust Region/Clipping 限制偏移。
- **证据/结论：** 达到相同下游性能时，RL 对原始通用能力的遗忘显著少于 SFT；论文将其归因于 On-Policy 自我一致性和受约束更新。
- **工程价值：** 若目标是激发已有能力而非灌入全新知识，可优先尝试带参考策略约束的 On-Policy RL，并用通用能力回归集选检查点。
- **限制：** 抗遗忘也可能受 KL、裁剪、学习率和训练量影响；RL 依赖可靠奖励且采样昂贵，并非所有配置都有同等保护。

在 LLM 的后训练（Post\-training）阶段，我们通常面临一个经典的权衡：如何在提升下游特定任务（Downstream Task）性能的同时，尽可能保持预训练模型（Pre\-trained Model）的通用能力。

最近 arXiv 上的一篇论文《Retaining by Doing》揭示了一个颇具反直觉的现象：**在达到相同下游任务性能的前提下，强化学习（RL）相比于监督微调（SFT），对原始通用能力的遗忘程度显著更低。**

### 问题定义：SFT 与 RL 的本质差异

为了讨论遗忘问题，我们首先需要明确两种范式的定义（Setup）：

- **SFT（Supervised Fine-Tuning）：**本质是 **Behavior Cloning（BC）**。给定专家策略生成的轨迹（Prompt + Gold Response），最小化负对数似然：

  $$
  \mathcal{L}_{\text{SFT}}(\theta)
  =
  -\mathbb{E}_{(x,y)\sim\mathcal{D}_{\text{expert}}}
  \left[
  \sum_{t=1}^{|y|}\log\pi_\theta(y_t\mid x,y_{<t})
  \right].
  $$

  这里的 SFT 数据分布通常只包含下游任务，不包含预训练数据。

- **RL（Reinforcement Learning）：**这里指 PPO 或 GRPO 等策略优化方法。一个常见的带 KL 约束目标为：

  $$
  \max_\theta\;
  \mathbb{E}_{\substack{x\sim\mathcal{D},\\ y\sim\pi_\theta(\cdot\mid x)}}[R(x,y)]
  -
  \beta\,
  \mathbb{E}_{x\sim\mathcal{D}}
  \left[
  D_{\mathrm{KL}}\!\left(
  \pi_\theta(\cdot\mid x)\,\|\,\pi_{\text{ref}}(\cdot\mid x)
  \right)
  \right],
  $$

  其中 $\pi_\theta$ 是当前策略，$\pi_{\text{ref}}$ 是参考策略（通常为初始模型）。

### SFT 致遗忘的机理：Off\-Policy 的强制拟合

SFT 的核心风险在于其 **Off\-Policy** 的特性。

在 SFT 过程中，训练分布 $p_{\text{SFT}}$ 由外部专家或更强模型给定。它往往高度特化，与预训练通用分布 $p_{\text{pre}}$ 存在显著的 Domain Shift。

SFT 的优化目标是让模型拟合 $p_{\text{SFT}}$。这就好比不仅要求模型学会“开汽车”（下游任务），还要求它严格模仿教练的每个细微动作。如果下游最优动作空间与模型原有能力不重叠，为了最小化 Cross-Entropy Loss，梯度下降会驱动参数大幅偏离原始区域。

**逻辑结论：** SFT 导致的是 **Distribution Shift（分布平移）**。由于缺乏对原始分布的约束，模型为了迎合局部最优解（SFT 数据），会不可避免地破坏参数原本的全局特征，从而导致严重的灾难性遗忘。

### RL 抗遗忘的机理：On\-Policy 与分布锐化

相比之下，RL 展现出天然的抗遗忘特性，论文将其归结为 **“Retaining by Doing”**。其优势主要源于以下两点：

#### A\. On\-Policy Data 的自我一致性

RL 的训练数据（Trajectory）是模型自己采样生成的。 这意味着，模型生成的 Responses 天然处于其当前的参数分布之内。RL 的过程不是在模仿一个“异质”的外部专家，而是在**模型已有的能力边界内进行筛选**。

模型通过“做”（Doing/Sampling）来探索解决路径。这种 On\-Policy 的数据生成方式，保证了语言风格、逻辑链路与模型本身的内在一致性。模型不需要为了模仿某种陌生的表达方式而破坏原本的权重结构。

#### B\. 优化目标的约束性

RL 的优化过程包含两个关键的维稳机制，这在 SFT 中是缺失的：

1. **KL Divergence Penalty：**RL 的 Loss 显式包含 $\beta D_{\mathrm{KL}}(\pi_\theta\|\pi_{\text{ref}})$。这在数学上给出了明确约束：**优化可以，但不能离初始模型太远。** 当参数试图剧烈偏移以获取更高 Reward 时，KL Loss 会产生反向梯度将其拉回。

2. **Trust Region / Clipping （如 PPO）：**不同于 SFT 只要 Loss 大就大幅更新，RL（特别是 PPO）通过 Clip 机制限制了单步更新的幅度（Trust Region）。它剔除了那些会导致概率比率（Ratio）剧烈波动的更新请求。

**逻辑结论：** RL 导致的是 **Distribution Sharpening（分布锐化）**。 RL 并没有试图将分布平移到未知的区域，而是压低低分路径的概率，拔高高分路径的概率。它是在“雕琢”原有的分布，而非“重塑”。因此，模型能够在掌握新任务（高 Reward）的同时，保留住那些未被负反馈抑制的通用能力。

### 总结与推论

我们可以用一个直观的类比来总结上述分析：

- **SFT 类似于“死记硬背”：** 给定标准答案，强行让模型记住。如果标准答案的逻辑与模型原有的认知体系冲突，模型会被迫覆盖原有认知，导致遗忘。

- **RL 类似于“自我修正”：** 模型用自己的知识去尝试解题，裁判给出分数。模型只是强化了自己思维中“对”的那部分。这种基于自身分布的探索（On\-Policy Exploration）配合 KL 约束，天然地保护了模型的基座能力。

这解释了为什么 DeepSeek\-R1 等工作倾向于使用强化学习来激发推理能力。**RL 不仅是提升能力的手段，更是保护模型通用性（Generalization）的有效屏障。** 在后训练阶段，如果我们希望模型在特定任务上精进且不丢失通用智商，应当更多地依赖 RL 的分布锐化机制，而非 SFT 的分布平移机制。

## On-Policy Distillation 【2025-10-27】 {#on-policy-distillation}

- **问题：** RL 的终局回报稀疏；Off-Policy 蒸馏只覆盖教师常见状态，学生一旦早期出错，就会进入训练未覆盖状态并累积偏差。
- **方法：** 从学生策略采样轨迹，让教师对学生实际到达的每个状态提供 Token 级概率，并以 Reverse KL 逼近教师；零折扣只优化立即的下一个 Token。
- **证据/结论：** 在内部文档与聊天数据 70/30 混合实验中，On-Policy 蒸馏几乎恢复 IF-eval 且未损失知识，并以更少步骤复制 RL 能力；有限批次梯度仍可能逐步造成策略漂移。
- **工程价值：** 适合推理、个性化、工具使用和成本预算等行为蒸馏：学生负责采样，教师只做前向打分即可提供稠密监督。
- **限制：** 需要教师完整 Token LogProb，不适用于纯文本黑箱 API；教师前向仍昂贵，Reverse KL 与有限批次误差也可能造成模式收缩和 Off-Policy 漂移。

### 背景

- **Pre\-training** teaches general capacities such as language use, broad reasoning, and world knowledge\.
预训练教会了语言使用、广泛推理和世界知识等一般能力。

- **Mid\-training** imparts domain knowledge, such as code, medical databases, or internal company documents\.

#### 损失函数：Reverse KL

对提示 $x$ 和由学生策略采样的前缀 $y_{<t}$，Token 级 On-Policy 蒸馏目标可写为：

$$
\mathcal{L}_{\text{OPD}}(\theta)
=
\mathbb{E}_{\substack{x\sim\mathcal{D},\\ y_{<t}\sim\pi_\theta}}
\left[
D_{\mathrm{KL}}\!\left(
\pi_\theta(\cdot\mid x,y_{<t})
\,\|\,
\pi_T(\cdot\mid x,y_{<t})
\right)
\right].
$$

展开单个状态上的反向 KL：

$$
D_{\mathrm{KL}}(\pi_\theta\|\pi_T)
=
\sum_{v\in\mathcal{V}}
\pi_\theta(v)
\log\frac{\pi_\theta(v)}{\pi_T(v)}.
$$

<ZoomableImage src="/paper-reading/assets/截屏2025-10-29%2009.25.38.png" alt="截屏2025-10-29 09.25.38.png" />

促使学生在它所处的每个状态下都去逼近教师的行为。当学生的行为与教师完全一致时，反向 KL 散度为零。使用零折扣因子，学生只优化立即的下一个标记，不考虑未来的标记。

优点：它不需要完成采样来计算奖励。查询教师的日志概率也只需要大型模型的一次前向传播，而轨迹则由小型且更经济的学生模型生成。

## Training-Free Group Relative Policy Optimization 【2025-10-09】 {#training-free-grpo}

- **问题：** 参数级 GRPO 需要训练基础设施和大量数据，还可能让模型偏科或遗忘；希望在冻结模型时复用组内比较信号。
- **方法：** 对同一问题生成多份答案，组内比较好坏，把差异总结为自然语言经验并累积到可插拔经验库；推理时检索相关经验作为提示。
- **证据/结论：** 数学与搜索各约 100 条样本即可提炼有效经验；但 QwQ-32B 搜索 Pass@1 从 27.5% 降至 25.5%，更强模型则获益明显。
- **工程价值：** 无训练、低数据、经验可编辑且按任务切换，适合快速适配小众领域并审计策略依据。
- **限制：** 需要清晰的优劣标准；经验跨任务迁移有限，弱模型可能无法执行经验，经验库还会带来检索、冲突和上下文成本。

paperlink: https://arxiv\.org/abs/2510\.08191

Codelink:  https://github\.com/TencentCloudADP/youtu\-agent/tree/training\_free\_GRPO

核心是 “**不训练参数，只积累经验”**。它会让模型对同一个问题生成多个解决方案（比如一道数学题，让模型出 5 种解题思路），然后让模型自己对比这些方案，找出哪种好、哪种差，再把 “为什么好” 的经验（比如 “解几何题要先确认点的位置是否在合理范围里”）用文字记下来，形成 “经验库”。之后再遇到类似任务，就把这些经验当作 “提示” 传给模型，指导它输出更好的结果。

从文档内容和方法原理来看，Training\-Free GRPO（无训练 GRPO）存在“潜在局限于特定类型问题”的可能性，但也通过设计降低了这种局限

### 一、可能“局限于某一类问题”？核心和“经验库的通用性”强相关

Training\-Free GRPO 的核心逻辑是“通过组内对比提炼自然语言经验，再用经验引导模型”——而“经验”的“通用性”直接决定了方法能否跨问题类型。如果经验是“高度场景化、难以迁移”的，就会导致方法局限于某一类问题。

#### 1\. 经验提炼依赖“问题有明确的‘优劣判断标准’”

方法的第一步是“对同一问题生成多个输出，判断哪些好、哪些差”——但这个“判断”依赖\*\*清晰的奖励信号或优劣标准\*\*：<br>

- 比如文档中测试的“数学推理”（答案有唯一正确值，对就是对、错就是错）、“网页搜索”（能否找到官方信息、是否完成查询目标，标准明确），这类问题能轻松让模型区分“好输出”和“差输出”，进而提炼出通用经验（比如“解几何题要验证点的位置是否在合理范围”“网页搜索优先点官方链接”）。<br>

- 但如果遇到“无明确优劣标准”的问题（比如创意写作、情感对话、开放域观点生成），既没有“正确答案”，也难定义“好输出”的统一标准（比如“写一首关于春天的诗，哪版更好”“安慰失恋的人，哪种回复更有效”），模型无法清晰对比输出优劣，自然难以提炼出有价值的经验——此时方法的效果会大幅下降，相当于“局限于有明确优劣标准的问题”。

#### 2\. 经验的“迁移性”受“问题类型相似度”影响

Training\-Free GRPO 的经验是“从特定问题中提炼的”，如果新问题和训练时的问题类型差异过大，经验可能“用不上”：<br>

- 比如从“数学几何题”中提炼的经验（“验证坐标是否符合几何约束”），无法迁移到“网页搜索”（需要的是“如何筛选关键词、判断链接权威性”）；同理，从“英文网页搜索”中提炼的经验（“优先。gov/\.edu 域名”），也难以迁移到“中文社交媒体信息检索”（需要关注“账号认证、内容点赞量”）。<br>

- 文档中提到它能同时做好“数学推理”和“网页搜索”，本质是因为这两类任务都有“明确优劣标准”，且分别为它们提炼了“专属经验库”（数学经验库、搜索经验库）——如果换一个完全无关联、且标准模糊的任务（比如“给产品写创意广告语”），现有经验库完全失效，需要重新用少量样本提炼新经验，相当于“对新类型问题需要重新适配，而非直接通用”。

#### 3\. 模型自身的“基础能力”会限制跨问题类型的适配

方法的效果依赖“基础模型能理解经验、并应用到新问题”——如果基础模型本身在某类问题上能力薄弱，即使给了经验，也难以发挥作用：<br>

- 文档中提到，当把方法用到“QwQ\-32B”（一个能力较弱的小模型）上时，网页搜索任务的表现反而比基线还差（25\.5% pass@1 vs 基线 27\.5%），原因是这个小模型本身“缺乏复杂工具使用和推理能力”，无法理解经验库中“如何优先选择官方链接、迭代优化搜索关键词”的指导；而用在能力强的“DeepSeek\-V3\.1\-Terminus”上时，效果显著。<br>

<ZoomableImage src="/paper-reading/assets/截屏2025-10-11%2011.11.54.png" alt="截屏2025-10-11 11.11.54.png" />

<ZoomableImage src="/paper-reading/assets/截屏2025-10-11%2011.12.06.png" alt="截屏2025-10-11 11.12.06.png" />

- 这意味着：如果遇到“基础模型本身不擅长”的问题类型（比如小模型做复杂逻辑推理、非英语模型做英语法律文档检索），即使方法本身能提炼经验，模型也无法应用，相当于“方法的适用范围被基础模型的能力边界限制”。

### 二、但通过设计，也降低了“局限于某一类问题”的风险

相比传统的“参数微调”（微调后模型容易“偏科”，练了数学就不会搜网页），Training\-Free GRPO 的设计天然有“抗局限”的优势，核心是“不改模型参数，只换经验库”：

#### 1\. “经验库可插拔”：换问题类型时，只需换经验，不用换模型

传统参数微调的问题是“模型参数被改造成适配某类问题”，比如用数学数据微调后，模型在其他任务上的能力会下降（即“灾难性遗忘”）；而 Training\-Free GRPO 的模型参数全程“冻结不变”，适配新问题时只需：<br>

- 用少量新问题样本（比如 100 个），按“生成多输出→对比优劣→提炼经验”的流程，建一个“新经验库”；<br>

- 后续调用模型时，把“新经验库”融入提示，模型就能用原有基础能力\+新经验解决新问题。<br>

比如文档中，同一个“DeepSeek\-V3\.1\-Terminus”模型，既能用“数学经验库”解数学题，又能用“搜索经验库”做网页搜索——只要给对应经验，就能适配对应问题类型，避免了“模型偏科”的局限。

#### 2\. 经验是“自然语言形式”：比“参数微调”更易跨场景迁移

传统参数微调的“知识”是隐含在模型参数里的，无法直接修改，且难以迁移；而 Training\-Free GRPO 的经验是“显式的自然语言规则”（比如“解几何题要验证点的位置”“搜索优先官方链接”），这种形式有两个优势：<br>

- 一是“可人工干预优化”：如果经验在新问题上不适用，可直接修改经验（比如把“优先。gov 域名”改成“优先。gov\.cn 域名”适配中文场景），不用重新训练；<br>

- 二是“跨小类型问题时更灵活”：比如从“平面几何”中提炼的“验证解的合理性”经验，可迁移到“立体几何”“代数方程求解”（核心逻辑都是“避免输出无意义的解”），而参数微调若只练了平面几何，在立体几何上效果会骤降。

#### 3\. 对“数据稀缺”的适应性：降低了“为每类问题攒大量数据”的门槛

传统参数微调要适配一类新问题，需要几千甚至几万条标注数据，否则会“学偏”；而 Training\-Free GRPO 只需几十到 100 条样本（文档中用 100 条数学样本、100 条搜索样本就实现了效果提升），就能提炼出有效经验。<br>

这意味着：即使是“小众类型的问题”（比如“古籍文献中的特定术语检索”“小众行业的技术计算”），只要能凑出少量样本，就能快速建经验库适配，不用因为“数据不够”而无法应用——相当于间接扩大了方法的适用范围，减少了“因数据稀缺而局限于大众问题”的风险。



## EEPO: Exploration-Enhanced Policy Optimization via Sample-Then-Forget 【2025-10-07】 {#eepo}

- **问题：** RLVR 容易反复利用已知高奖励解法，随着熵下降失去探索能力，并在新型问题上退化。
- **方法：** 先按当前策略生成一半样本，再在检测到低熵时做轻量、临时且针对高频旧策略的“遗忘”更新，随后生成另一半样本以探索不同路径。
- **证据/结论：** 笔记保留了重要质疑：EEPO 可能只是延缓而非消除熵崩塌，且部分曲线 Reward 更低；更稳妥的结论是它增加探索，但不保证任务收益。
- **工程价值：** 当任务存在多种有效策略且常规采样高度同质时，可把第二阶段去相关采样作为 Rollout 生成器插件。
- **限制：** 若探索收益低于利用收益，遗忘只会浪费样本；触发阈值和强度难调，过强会压制有效策略，过弱则没有新增多样性。

paperlink:https://arxiv\.org/abs/2510\.05837

分两步让模型探索新方法：第一步，让模型先按老习惯生成一半的解题思路（比如解 10 道题，先按熟悉的方法做 5 道）；第二步，给模型做个 “临时失忆”：让它暂时 “忘记” 刚生成的这 5 种思路，相当于抑制了它对 “老方法” 的依赖；最后，再让模型生成剩下的 5 道题思路 —— 这时候因为 “忘了” 老方法，模型就不得不去探索之前没试过的新解题路径了。

现在很多大模型是用 “带可验证奖励的强化学习（RLVR）” 来训练的，比如让模型解数学题，做对了给奖励、做错了没奖励，以此让模型越练越好。但这种训练有个大问题：模型会变得 “保守”。

怎么个保守法呢？比如模型发现一种解数学题的方法总对，就会一直用这一种，不再尝试其他可能更优的方法（这叫 “过度利用”）。时间一长，模型的 “探索能力” 会越来越弱，甚至只会机械重复老方法（这叫 “熵崩溃”）。更麻烦的是，这样训练出的模型，在熟悉的题目上可能表现不错，但遇到没见过的新类型题目（比如平时练基础题，考试考竞赛题），就会翻车 —— 因为它没探索过其他解题思路。

<ZoomableImage src="/paper-reading/assets/image%2014.png" alt="image.png" />

之前也有人想解决这个问题，比如让模型 “多瞎猜”（提高采样温度）、“强制多样化”（加熵正则），但这些方法要么没效果（还是老盯着老方法用），要么让模型变不稳定（猜得太乱，正确率下降）。

<ZoomableImage src="/paper-reading/assets/image%2042.png" alt="image.png" />

于是研究团队就提出了** EEPO**，核心思路是 “先采样、再忘记”，分两步让模型探索新方法：

<ZoomableImage src="/paper-reading/assets/image%201.png" alt="image.png" />

分两步让模型探索新方法：第一步，让模型先按老习惯生成一半的解题思路（比如解 10 道题，先按熟悉的方法做 5 道）；第二步，给模型做个 “临时失忆”：让它暂时 “忘记” 刚生成的这 5 种思路，相当于抑制了它对 “老方法” 的依赖；最后，再让模型生成剩下的 5 道题思路 —— 这时候因为 “忘了” 老方法，模型就不得不去探索之前没试过的新解题路径了。

为了让这个 “失忆” 不搞砸模型本身，团队还加了三个小设计：

1. 不瞎失忆：只有当模型探索能力变弱（“熵” 变低）时，才触发失忆，平时不干扰；

2. 精准失忆：重点 “压制” 模型最常用的老方法，对少见的新方法不怎么管；

3. 轻量失忆：只给模型做个 “临时微调”，不改变核心能力，下次训练又会恢复，不会让模型 “学废了”。

## What Characterizes Effective Reasoning? Revisiting CoT Quality 【2025-09-23】 {#cot-reasoning-quality}

- **问题：** 长 CoT 或频繁自检不等于高质量推理，可能只是绕路、重复和新增错误，需要结构性指标。
- **方法：** 把思维链转为推理图，将放弃或失败尝试标成失败节点，计算失败步骤占比 FSF，并用于同题多条 CoT 排序。
- **证据/结论：** 跨模型和任务中 FSF 越低正确率越高；从 64 条思维链按 FSF 选 Top-1，相比随机提升 5%～13%，优于长度或检查次数排序。
- **工程价值：** FSF 可用于 Best-of-N 重排、轨迹清洗或作为 RL 奖励分量，帮助识别失败分支过多的低效轨迹。
- **限制：** 推理图和失败节点判定可能依赖另一个模型；相关性不等于因果性，探索任务中的失败尝试也可能具有信息价值。

paperlink: https://arxiv\.org/abs/2509\.19284

“思考长度” 和 “检查次数” 只是表面指标 —— 比如有的模型思考长，其实是在反复绕路、做无用功；有的检查多，却没解决核心问题。真正重要的是 “思考过程的结构”，比如有没有走弯路、有没有放弃错误的思路。

所以他们想了个办法：把模型的思考过程画成 “思维导图”（叫 “推理图”），每个节点代表一个思考步骤，红色节点代表 “失败的尝试”（比如试了一种方法发现走不通，就放弃了）。然后算了个指标叫 **“失败步骤占比（FSF）”** —— 也就是失败的思考步骤占所有步骤的比例。

### 失败步骤占比（FSF）才是 “思考质量” 的核心

测试后发现，FSF 比 “长度” 和 “检查次数” 靠谱多了：

- 不管是哪个模型、解数学题还是科学题，**FSF 越低（失败步骤越少），正确率越高**，而且这个规律在简单题、难题里都成立；

- 哪怕有个模型（Claude 3\.7）特别喜欢回头检查（按之前的指标看 “检查多”），但只要它的 FSF 低，正确率依然高 —— 这说明 “检查多” 本身没用，关键是别在检查时产生更多失败步骤。

#### 可以在 RL 中作为一个 Reward：用 FSF 做 “优先级评分”，选最优输出

文档实验显示 “按 FSF 排序选 top1，正确率比随机高 5%\-13%”，可将 FSF 作为核心评分指标，优化结果筛选逻辑：

- 流程：对同一个问题，让模型生成 10\-20 条不同的思维链，用工具（如 Graphviz）把每条链转成 “推理图”，计算每条的 FSF，再结合 “长度”“回顾比例”，给每条思维链打分（比如 FSF 占 60% 权重，长度占 30%，回顾比例占 10%），最终输出评分最高的 1\-2 个结果；

- 优势：比单纯 “按长度排序” 或 “随机选” 更精准，尤其适合高难度任务（如科研公式推导、复杂工程计算）



## Agentic Reinforced Policy Optimization 【2025-07-26】 {#agentic-rpo}

- **问题：** 工具调用后不确定性常升高，固定数量的完整 Rollout 会错过关键分叉或浪费预算；整轨迹奖励也难归因到具体工具操作。
- **方法：** ARPO 监测工具调用后的 Token 熵变化，只在高熵局部追加分支；再把轨迹拆成共享与独有 Token 段，为两者分别计算并映射优势。
- **证据/结论：** 笔记记录了工具调用后若干 Token 熵升高的观察；自适应 Rollout 将预算集中到潜在分叉，硬优势归因避免关键信号被整轨迹稀释。
- **工程价值：** 适合搜索、代码解释器等多步 Agent：用熵决定哪里多采样，用分段归因判断哪种补充搜索或计算真正有效。
- **限制：** 高熵不必然代表高价值，也可能只是工具噪声；局部分支增加调用成本，硬前缀切分也难覆盖语义相同但 Token 不同的轨迹。

codelink: https://github\.com/dongguanting/ARPO

paperlink: https://arxiv\.org/abs/2507\.19849

现在很多大模型能用工具帮忙解决问题，但之前的训练方法有个缺点 —— 要么只关注 “从头到尾完成一整套任务”（比如搜资料→写答案的完整流程），要么没考虑到模型用工具后会变得 “犹豫”（比如调用搜索后，模型接下来该输出什么的不确定性会变大），导致模型要么不会灵活用工具，要么用工具时浪费太多资源。

研究团队先发现了一个关键现象：大模型每次用完工具后，生成内容的 “不确定性”（文档里叫 “熵”）会突然升高 —— 比如调用搜索拿到结果后，模型接下来的 10\-50 个输出内容，不确定该选哪个词的情况会变多。这说明用工具后模型其实有很多潜在的思考方向，但之前的方法没利用好这个特点。

<ZoomableImage src="/paper-reading/assets/image%2015.png" alt="image.png" />

于是设计了 ARPO 算法，核心就是解决这个问题，主要靠两招：

第一招是 “根据不确定性灵活探索”：模型先用常规方式生成一些完整的任务流程（比如搜资料→推理→写答案），同时盯着 “用工具后的不确定性”——** 如果不确定性超过某个阈值，就专门在这个步骤多试几种不同的思考路径**（比如搜完后，既试 “先整理资料再推理”，也试 “先挑关键信息再补充搜索”），这样既不会漏掉潜在的好方法，也不用在确定的步骤上浪费精力。

第二招是 “帮模型记住哪种做法更好”：因为模型会试多种路径，ARPO 会专门计算 “哪种路径更有用”—— 比如同样是用搜索，有的路径能更快找到答案，就给这种路径更高的 “奖励分”，让模型慢慢学会优先选更有效的工具使用方式。

<ZoomableImage src="/paper-reading/assets/image%2036.png" alt="image.png" />

1. 输入问题（Question，$q$）

流程从用户的问题 $q$ 开始，比如“请用工具帮我解决这个数学题”。

2. Rollout Module（推演模块）

- Policy Model（策略模型）：大语言模型本身，负责决定 “何时调用工具、调用什么工具、怎么用工具”。

- Tool Environment（工具环境）：外部工具的集合（如搜索引擎、代码解释器）。模型在这个模块里，根据问题 $q$ 尝试和工具互动，生成一系列行动序列（比如“调用搜索→输入关键词→获取结果→推理计算”）。

3. Entropy \- based Adaptive Rollout（基于熵的自适应推演）

- Entropy（熵）：衡量模型生成内容的 “不确定性”（比如调用工具后，模型不确定接下来该输出什么时，熵就高）。

- Global（全局）和 Partial（局部）：把模型生成的行动序列分成两部分。

    - 全局部分（$o_1,\ldots,o_{n_1}$）：模型对这部分“比较确定”（熵低），所以少试几种变化。

    - 局部部分（$o_{n_1+1},\ldots,o_{n_1+n_2}$）：模型对这部分“很不确定”（熵高），所以多试几种不同的行动路径（比如调用搜索后，既试“整理资料→计算”，也试“补充搜索→计算”）。这样做是为了高效探索：不在确定步骤浪费精力，而在不确定步骤多尝试。

4. Reference Model \& Reward Model（参考模型 \& 奖励模型）

- Reference Model（参考模型）：提供一个 “基准”，判断模型生成的行动序列 “好不好”。

- Reward Model（奖励模型）：给不同的行动序列打分（$r_1,\ldots,r_{n_1+n_2}$）。

    - 全局部分的奖励（$r_1,\ldots,r_{n_1}$）：因为模型对这部分确定，奖励相对稳定。

    - 局部部分的奖励（$r_{n_1+1},\ldots,r_{n_1+n_2}$）：因为模型多试了不同路径，奖励会体现哪种路径更有用。

5. Group Computation（分组计算）

把全局和局部的奖励整合起来，计算 “哪组行动序列整体更优”。

6. Advantage（优势）

- Advantage（优势）：衡量当前行动序列比平均水平好多少（$A_1,\ldots,A_{n_1+n_2}$）。

    - 全局部分的优势（$A_1,\ldots,A_{n_1}$）：反映全局行动的超额价值。

    - 局部部分的优势（$A_{n_1+1},\ldots,A_{n_1+n_2}$）：反映局部阶段尝试的不同路径中哪条更有优势。

7. Advantage Attribution Estimation（优势归因估计）

把 “优势” 反馈给前面的模块（虚线箭头），让模型记住 “哪种工具使用策略更优”，下次遇到类似问题时，优先选优势高的策略。

### 熵变化监测的过程

<ZoomableImage src="/paper-reading/assets/截屏2025-10-12%2020.25.17.png" alt="截屏2025-10-12 20.25.17.png" />

熵变化监测的过程，用于跟踪大模型在调用工具后生成内容的不确定性是如何变化的，步骤如下：

1. 初始熵记录：首先记录模型在工具调用前的初始熵 $H_{\text{initial}}$，作为基准值。

2. 带工具的智能推理：模型结合工具进行智能推理（如公式 2 所定义的那样）。

3. 工具调用后的 Token 生成与熵计算：每次工具调用后，把工具结果拼接到已有内容，让模型再生成 $k$ 个 Token。对于第 $t$ 步工具调用，计算步骤级熵向量 $H_t\in\mathbb{R}^{1\times k}$，其中每个元素对应一个生成 Token 的熵。

4. 熵变化的量化：相对初始状态的归一化熵变化写为：

   $$
   \Delta H_t
   =
   \operatorname{Normalize}\!\left(H_t-H_{\text{initial}}\right).
   $$

   这里的归一化是对 $\Delta H_t$ 的元素求和后除以词汇表大小 $V$。若 $\Delta H_t>0$，说明工具调用后生成内容的不确定性增加；若 $\Delta H_t<0$，则说明不确定性降低。

简单来说，就是通过这样的方法，能清楚看到模型在调用工具的不同步骤后，生成内容是更不确定了还是更确定了，从而帮助分析模型结合工具推理时的行为特点。



### 优势归因估计（ADVANTAGE ATTRIBUTION ESTIMATION）

本章是 ARPO（基于熵的自适应滚动和优势归因优化）算法的核心模块之一，核心目标是解决传统优势估计在 “大模型与工具交互场景” 中存在的 “优势分配模糊” 问题 —— 即传统方法难以精准判断 “工具交互轨迹中哪一步行动对任务结果更关键”，最终通过明确的归因逻辑，让模型高效学习更优的工具使用策略。

**一、章节研究背景：传统优势估计的核心痛点**

在大模型训练中，“优势（Advantage）” 用于衡量 “某条行动轨迹（如‘调用搜索→推理→输出答案’）比平均水平的轨迹好多少”，是引导模型优化行为的关键信号。但在模型与工具交互的复杂任务中，传统优势估计存在两大核心问题：

1. 轨迹共享与独有部分混淆：模型尝试的多条工具交互轨迹（如 d 条轨迹）中，常存在 “共享步骤”（如所有轨迹前 3 步都是 “调用搜索→输入关键词→获取结果”）和 “独有步骤”（如部分轨迹第 4 步是 “直接推理”，另一部分是 “补充搜索后推理”）。传统方法会将整体优势平均分配给所有步骤，无法区分 “共享步骤的通用价值” 和 “独有步骤的差异化价值”，导致模型无法精准学到 “哪一步工具选择更有效”。

2. 工具交互步骤的优势稀释：在多步工具调用任务（如多轮搜索、多步代码计算）中，任务结果的好坏往往由某几个关键工具交互步骤决定（如 “补充搜索” 这一步是否能获取关键信息），但传统优势估计会将优势分散到所有步骤，导致关键步骤的优势信号被稀释，模型难以聚焦优化核心工具使用行为。

**二、核心方法：硬性优势估计（Hard Advantage Estimation）**

为解决上述问题，本章提出 “硬性优势估计” 框架，通过明确区分轨迹的 “共享 token 段” 与 “独有 token 段” ，实现优势的精准归因，具体分为 3 个关键步骤：

1. 轨迹分段：划分共享 token 与独有 token

首先对模型生成的 $d$ 条工具交互轨迹分段。第 $i$ 条轨迹记为：

$$
\tau_i=\left[o_1^{(i)},o_2^{(i)},\ldots,o_T^{(i)}\right],
$$

其中 $o_t^{(i)}$ 是第 $i$ 条轨迹的第 $t$ 个 Token，$T$ 是轨迹长度。

- 共享 Token 段（Shared Tokens）：所有 $d$ 条轨迹中完全相同的连续序列，记为 $S=[o_1,o_2,\ldots,o_m]$，其中 $m$ 为共享段长度。这部分是解决任务的基础通用行为。

- 独有 Token 段（Unique Tokens）：第 $i$ 条轨迹在共享段后的差异化序列，记为 $U_i=[o_{m+1}^{(i)},\ldots,o_T^{(i)}]$，其中 $i=1,\ldots,d$。这部分表示差异化工具策略，是优势归因的重点。

*示例*：若 3 条轨迹分别为：

- 轨迹 1：调用搜索→输入关键词→获取结果→直接推理→输出

- 轨迹 2：调用搜索→输入关键词→获取结果→补充搜索→推理→输出

- 轨迹 3：调用搜索→输入关键词→获取结果→调用代码计算→推理→输出则 “调用搜索→输入关键词→获取结果” 为共享 token 段，后续的 “直接推理”“补充搜索→推理”“调用代码计算→推理” 分别为 3 条轨迹的独有 token 段。

2. 优势计算：分阶段量化不同段落的价值

本章通过 “分阶段计算”，分别量化共享段和独有段的优势，避免优势混淆：

**（1）共享段优势 $A_{\text{shared}}$**

共享段的优势反映 “基础通用步骤对所有轨迹的平均贡献”，计算逻辑为：

- 先计算所有 d 条轨迹的 “总优势”（即每条轨迹的收益与所有轨迹平均收益的差值）；

- 由于共享段是所有轨迹的共同基础，其优势取所有轨迹总优势的平均值：

  $$
  A_{\text{shared}}
  =
  \frac{1}{d}\sum_{i=1}^{d}A_i^{\text{total}},
  $$

  其中 $A_i^{\text{total}}$ 是第 $i$ 条轨迹的总优势。

- 意义：让模型明确 “完成基础工具操作（如调用搜索并获取结果）是所有有效轨迹的前提，具有稳定的基础价值”。

**（2）独有段优势 $A_{\text{unique}}^{(i)}$**

独有段的优势反映 “某条轨迹的差异化策略比其他轨迹的差异化策略好多少”，计算核心是 “归一化差异”：

- 先计算第 $i$ 条轨迹的总收益与组平均收益之差 $\Delta R_i=R_i-\bar{R}$，其中 $R_i$ 是该轨迹收益，$\bar{R}$ 是 $d$ 条轨迹的平均收益。

- 将 $\Delta R_i$ 除以所有轨迹收益差的绝对值之和，得到归一化独有段优势：

  $$
  A_{\text{unique}}^{(i)}
  =
  \frac{\Delta R_i}{\sum_{j=1}^{d}|\Delta R_j|}.
  $$

- 意义：通过归一化，放大 “更优差异化策略” 的优势信号 —— 例如，若轨迹 2 的 “补充搜索” 策略带来的收益差远高于其他轨迹，则其独有段优势会显著更高，模型能清晰感知 “补充搜索这一差异化操作更有价值”。

3. 优势归因：将优势映射到 token 级，引导模型学习

完成分段优势计算后，本章将优势 “精准映射到每个 token”，形成 “token 级优势序列”，直接用于模型参数更新：

<ZoomableImage src="/paper-reading/assets/截屏2025-10-12%2020.34.07.png" alt="截屏2025-10-12 20.34.07.png" />

- 共享段的每个 Token：均分配共享段优势 $A_{\text{shared}}$，确保模型记住基础工具操作的必要性；

- 第 $i$ 条轨迹独有段的每个 Token：均分配 $A_{\text{unique}}^{(i)}$，让模型识别该差异化工具策略的价值。

*关键作用*：通过 token 级的精准归因，模型在更新时能 “逐步骤学习”—— 对于共享段，强化基础工具操作；对于独有段，优先强化优势高的差异化策略（如补充搜索），从而逐步形成更高效的工具使用习惯。

## Learning without Training: The Implicit Dynamics of In-Context Learning 【2025-07-21】 {#icl-implicit-dynamics}

- **问题：** Transformer 为什么仅凭上下文示例就表现得像经过训练，其内部更新机制缺少可计算解释。
- **方法：** 用“注意力层 + MLP”的上下文块抽象 Transformer，证明带上下文输出等价于无上下文网络第一层权重的一次低秩更新，逐 Token 动力学类似逐渐收敛的梯度下降。
- **证据/结论：** 本条以理论等价为主：ICL 不修改持久参数，却可在前向过程中实现类似参数适配的效果。
- **工程价值：** 为示例排序、上下文压缩、低秩适配器和测试时学习提供统一直觉。
- **限制：** 上下文块是简化模型，未必完整覆盖深层 Transformer、位置编码和真实生成误差，不能直接当作部署算法。

paperlink: https://arxiv\.org/abs/2507\.16003v1

提出了一个叫 “上下文块” 的概念。可以把它理解成 “注意力层 \+ 普通神经网络（比如 MLP 层）” 的组合，这其实是对 transformer 模型结构的一种概括。文章证明了：这个 “上下文块” 能把提示词里的 “上下文信息”，悄悄变成神经网络第一层权重的 “低秩更新”—— 简单说就是，有上下文时模型的输出，和 “没上下文但给模型权重做个小调整” 的输出是一样的，而且这个权重调整的规律能通过公式算出来。

解释了模型处理上下文时的 “隐性学习过程”。当模型一句句读提示词里的内容时，每读一个词，都会对应一次权重的隐性调整，这个过程很像我们训练模型时用的 “梯度下降”—— 就像学东西时一步步修正错误，而且越往后，新内容带来的调整越小，直到稳定下来，这也和实验结果一致。

## Don’t Just Fine-tune the Agent, Tune the Environment 【2025-10-11】 {#tune-the-environment}

- **问题：** SFT 容易机械模仿，纯 RL 又会因早期无经验、终局奖励稀疏和错误反馈含糊而陷入低效试错。
- **方法：** 优化环境本身：从工具格式到复杂任务做课程学习，让错误响应给出原因与可行动建议，并把终局奖励拆成中间步骤奖励。
- **证据/结论：** 原始笔记的核心结论是细化 Tool Response 与 Reward 本身就是训练手段；当前摘录未保留具体实验数字。
- **工程价值：** 改进错误码、参数校验、可恢复状态和阶段性 Verifier，往往能同时提高训练效率与线上自愈能力。
- **限制：** 高质量课程与过程奖励需要领域设计；提示过强会泄漏答案，稠密奖励可能被投机，模拟环境偏差也会迁移到策略。

paperlink: https://arxiv\.org/abs/2510\.10197

简单来说，以前训练这类 AI 有两个常见问题：要么用 “监督微调”（给 AI 喂现成的示例轨迹），但 AI 容易学死，遇到没见过的情况就不行；要么用 “强化学习”（让 AI 在环境里试错学习），但 AI 一开始没经验，容易陷入无效试错，训练还不稳定。

于是研究者提出了 “环境调优”（**ENVIRONMENT TUNING**）这种新方式：

1. 分阶段教学：先让 AI 练基础（比如正确调用工具的格式，别写错参数），再练简单任务，最后挑战复杂场景，一步一步来，避免 AI 一开始就懵；

2. 环境给有用反馈：以前 AI 犯错，环境可能只说 “错了”，现在会明确指出来 “错在哪”“怎么改”—— 比如 AI 订机票时用了错误的机场代码，环境会提示 “机场代码无效，你可以用工具查正确代码”，而不是只说 “没这条航线”；

3. 细化奖励机制：以前 AI 只有完成整个任务才给奖励，现在每一步做得好都给反馈 —— 比如订机票时，先查对机场代码算一步成功，再查到航班价格又算一步，哪怕最后没订完，也能从中间步骤里学东西，不用一直瞎试。

## Agent Learning via Early Experience 【2025-10-13】 {#agent-early-experience}

- **问题：** 模仿学习不会利用 Agent 自己的错误，纯 RL 又要求明确奖励且试错昂贵；很多真实界面只有状态变化而没有标量回报。
- **方法：** 先用少量专家演示建立起点，再让 Agent 主动尝试并观察后果；一条路线学习隐式世界模型，另一条路线对照专家行动进行自我反思。
- **证据/结论：** 日期错误、页面跳转和预算选择等例子表明，环境后果本身可以成为无需显式奖励的学习信号；摘录未记录量化基准。
- **工程价值：** 可把真实工具的参数校验、状态迁移和失败响应转成训练对，适合奖励难定义但环境反馈丰富的业务 Agent。
- **限制：** 主动试错必须在隔离环境内；状态变化可能含糊或延迟，世界模型会累积误差，自我反思也可能产生错误因果解释。

paperlink:  https://arxiv\.org/abs/2510\.08558

AI 学东西的两种常见方式：一种是 “模仿学习”，就是 AI 照着人类专家做好的示范学（比如学订机票就看人类怎么点网页），这种不用环境给奖励，但 AI 只能被动模仿，不会从自己的错误里学，遇到没见过的情况就容易 “懵”；另一种是 “强化学习”，AI 靠试错学，环境给奖励（比如完成任务给高分）才能进步，但很多真实场景里没有明确奖励（比如填个表单，AI 不知道填对没），而且试错过程又慢又复杂。

而 “早期经验学习” 就是卡在这两种方式中间的好办法：**AI 先学一点人类示范，然后自己在环境里尝试不同行动（比如订机票时故意点错按钮、填错日期），观察这些行动带来的结果（比如出现错误提示、页面跳转变化），把这些 “自己试出来的经验” 变成学习信号，不用等环境给奖励。**

具体怎么用这些经验呢？文档给了两个办法：第一个是 “隐性世界建模”，AI 会学着预测自己行动后的结果。比如学订机票时，AI 会记住 “填错日期会出现‘日期无效’提示”，慢慢摸清环境的规律，下次遇到类似情况就知道该怎么选。第二个是 “自我反思”，AI 会对比自己的行动和人类专家的行动，想清楚 “为啥专家选这个而不是那个”。比如选衣服时，专家选 15 美元的蓝色款，AI 自己试了 30 美元的红色款，就会反思 “红色虽然好看，但超了 20 美元预算，蓝色既符合风格又省钱”，这样下次遇到预算问题就知道优先考虑什么。

## ToolMem: Enhancing Multimodal Agents with Learnable Tool Capability Memory {#toolmem}

- **问题：** 多模态 Agent 对工具优缺点缺乏跨任务积累，容易重复选择不擅长相应细粒度能力的工具。
- **方法：** 为能力建立从 +2 到 -2 的分级记忆，调用后从反馈中抽取、合并和纠正结论，新任务再检索相关记忆以辅助工具选择与效果预估。
- **证据/结论：** 原始笔记记录，基础模型越强，ToolMem 的提升空间越小，因此它更像对工具认知不足的补偿层。
- **工程价值：** 可把历史调用日志转成显式 Tool Profile，支持工具路由、失败规避和小模型训练。
- **限制：** 工具能力具有任务条件和版本时效，反馈误归因会污染记忆，检索过多还会挤占上下文；末尾的工具比例设想仍是待验证假设。

paperlink: https://arxiv\.org/abs/2510\.06664

给 AI 助手加了一个 “工具能力记忆库”，让 AI 能从之前用工具的经历里，总结出每个工具的长处（比如 “擅长画带文字的图”）和短处（比如 “不会精准定位物体位置”），然后存起来。等下次遇到新任务时，AI 会先从这个记忆库里调出相关信息，再选最合适的工具。

1. **先搭好记忆框架**：给每个工具的能力分了类，比如 “很擅长（\+2 分）”“比较擅长（\+1 分）”“不太擅长（\-1 分）”“很不擅长（\-2 分）”，这样 AI 记的时候有条理，后续找起来也方便。

2. **从经验里学东西**：AI 用工具干活后，会拿到反馈 —— 可能是人的评价，也可能是系统给的分数（比如 “这个图没画准文字，给 3 分”）。AI 会根据这些反馈，总结出工具的能力（比如 “这个画图工具画文字不行”），然后更新到记忆库里，还会自动合并重复信息、修正之前记错的内容，避免内存乱糟糟。

3. **用记忆选工具干活**：遇到新任务时，AI 会先从记忆库里找和当前任务相关的信息（比如要画带文字的图，就找 “擅长处理文字” 的工具记忆），再根据这些信息选工具、预估效果，最后完成任务。
