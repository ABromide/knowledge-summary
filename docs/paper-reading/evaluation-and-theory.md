## 数据相关

### 1. SECVULEVAL：真实世界 C/C++ 漏洞检测基准 {#secvuleval}

- **用途 / 问题**：判断大模型面对真实 C/C++ 代码时能否识别漏洞，而不只是在合成样例或单一漏洞模式上取得高分。
- **关键结论**：现有笔记保留了论文与两张结果截图，但未转录数据集构造、任务定义、指标或数值结论，因此不能仅凭截图推导模型优劣。
- **工程价值**：可作为安全代码 Agent 的候选离线基准入口，重点考察真实项目样本、漏洞定位粒度，以及误报和漏报是否分别统计。
- **限制 / 核验动作**：需回到论文逐项核对样本来源、训练数据重叠、基线模型、评测提示、指标定义和统计显著性；接入内部评测前还要确认许可证与数据可复现性。

### 2. SEER：基于逐步经验召回的自引导函数调用 {#seer-function-calling}

- **用途 / 问题**：解决多步骤函数调用依赖大量人工轨迹标注、工具组合长且模型难以从历史执行中持续学习的问题。
- **关键结论**：SEER 通过“**动态经验池 + 轨迹相似度、工具链覆盖率、意图匹配的三维细粒度检索**”复用历史步骤经验，实现多步骤函数调用的自引导持续优化；笔记认为它能减少人工标注、提高真实任务准确率，并随使用逐步自我改进。
- **工程价值**：适合用于工具型 Agent 的经验检索层：将成功或高价值 trace 沉淀为可召回经验，按当前意图与所需工具链筛选，降低重复规划和工具误选成本。
- **限制 / 核验动作**：动态经验池可能积累失败轨迹、过期工具说明和相似但不适用的步骤。落地时应绑定工具版本、执行结果与质量标签，并通过消融实验分别验证三个检索维度的增益，以及长链调用的延迟和 token 成本。

[论文：*Self-Guided Function Calling in Large Language Models via Stepwise Experience Recall*](https://arxiv.org/pdf/2508.15214)

## 评估方法

### 3. LLM-as-a-Judge：偏差修正与置信区间 {#llm-as-judge-calibration}

- **用途 / 问题**：处理 Judge 模型存在系统性判断偏差、单次分数缺少不确定性表达的问题。
- **关键结论**：使用一个**校验数据集**估计并修正大模型判断偏差，最终结果还应构建置信区间，而不是只报告校正后的点估计。
- **工程价值**：可将人工标注的小规模校验集作为 Judge 的标尺，把自动评测升级为“经过偏差校准、同时报告不确定性”的流程。
- **限制 / 核验动作**：校验集必须覆盖线上任务分布和主要错误类型，否则校正量无法外推。需要核对校正方法、置信区间假设、样本量敏感性，并按模型、任务和时间漂移定期重做校准。

### 4. CoDeC：通过上下文学习检测数据污染 {#codec-contamination-detection}

- **用途 / 问题**：在不知道训练语料明细时，判断某个评测数据集是否可能已被模型见过，避免把记忆能力误当成泛化能力。
- **关键结论**：加入同分布上下文后，未见数据通常因获得分布提示而置信度上升；已见数据则可能因冗余上下文干扰记忆提取而置信度下降。CoDeC 以这种置信度变化作为污染信号。
- **工程价值**：可在基准发布或模型选型前增加无训练集访问的污染筛查，并将污染分数与原始准确率并列报告。
- **限制 / 核验动作**：置信度下降并非污染的唯一原因，示例质量、顺序、长度、格式和模型是否开放 log-probability 都会影响结果。应使用多组随机上下文、已知污染/未污染对照集、置信区间和显著性检验。

- [论文：*Detecting Data Contamination in LLMs via In-Context Learning*](https://www.arxiv.org/pdf/2510.27055)

- [中文解读](https://www.mlpod.com/1234.html)

CoDeC 的核心思想：**对于一个给定的数据样本，模型对其预测的置信度（confidence）会因上下文中是否提供了来自同一数据分布的“提示”而发生不同的变化。这种变化的模式，恰好揭示了该样本是否是模型训练的一部分。**

#### 上下文学习对置信度的不同影响

当 LLM 处理一个任务时，我们可以通过在提示（prompt）中提供几个示例（in\-context examples）来引导其输出，这就是上下文学习。CoDeC 正是利用了这一机制。

1. **对于未见过（Unseen）的数据集：**

   假设模型从未在训练中见过 `gsm8k` 这个小学数学应用题数据集。当从 `gsm8k` 抽取一个问题作为目标样本时，模型只能基于通用语言和数学能力预测答案。如果提示中再加入一个来自 `gsm8k` 的问题及解答，上下文就提供了该数据集的风格、格式、难度和潜在解题模式。额外信息有助于模型理解目标样本，因此模型对正确答案序列的置信度（通常用对数概率 log-probability 衡量）会**上升**。

2. **对于已见过（Seen）的数据集：**

   假设模型在训练中已经“背诵”了 `ArXiv` 论文摘要数据集。当从 `ArXiv` 抽取一篇摘要让模型继续生成时，模型可高度自信地依据内部记忆预测后续 token。此时再提供另一篇 `ArXiv` 摘要作为上下文，新增信息可能是冗余的，甚至干扰目标样本的记忆提取，导致预测置信度**下降**。

#### CoDeC 的工作流程

<ZoomableImage src="/paper-reading/assets/image%2041.png" alt="image.png" />

<ZoomableImage src="/paper-reading/assets/截屏2025-12-10%2009.55.38.png" alt="截屏2025-12-10 09.55.38.png" />

令 $c_i^{\mathrm{base}}$ 表示目标样本 $i$ 在无同分布示例时的置信度，$c_i^{\mathrm{ICL}}$ 表示加入同分布上下文后的置信度，则置信度变化为：

$$
\Delta x_i = c_i^{\mathrm{ICL}} - c_i^{\mathrm{base}}.
$$

对数据集 $D$ 中的所有样本重复上述过程。最终的 CoDeC 分数定义为 $\Delta x_i < 0$ 的样本比例：

$$
\operatorname{CoDeC}(D) = \frac{1}{|D|}\sum_{i \in D}\mathbf{1}\!\left[\Delta x_i < 0\right].
$$

#### CoDeC 为何有效？

1. **数据集特有先验揭示污染：** 模型在训练某个数据集时，会内化其独特的风格、结构、词汇和隐含假设，这些构成了“数据集特有的先验”（dataset-specific priors）。如果这些先验已经被模型通过训练“记忆”下来，那么通过上下文样本再次提供这些信息就是多余的。

2. **上下文干扰记忆模式：** 对于被污染的数据，模型依赖的是一种较为“僵化”的记忆模式来预测词元序列。引入的上下文样本，即使来自同一分布，也会构成一个不同的语境，这会干扰或破坏模型既有的记忆通路，导致其预测置信度降低。

3. **ICL 模拟微调动态：** 上下文学习（ICL）在某种程度上可以看作是一种“即时微调”（in-the-moment finetuning）。对于未见过的数据，ICL 提供了有效的学习信号，模型能快速适应，性能提升。而对于已经见过（污染）的数据，模型已经处于“过拟合”或“饱和”状态，其学习潜力已经很小，额外的“微调”信号几乎不会带来增益，甚至可能因为扰动而产生负面效果。CoDeC 度量了模型对于特定数据集“剩余的学习容量”。

4. **干预暴露损失曲面：** 数据污染通常与过拟合相关。在损失函数的几何空间中，过拟合的样本对应着一个“狭窄而陡峭”的局部最小值。任何微小的输入扰动（例如增加上下文）都可能使模型“跌出”这个尖锐的谷底，导致损失增大（置信度降低）。相比之下，泛化良好的未见过样本对应着一个“平坦而宽阔”的区域，模型对输入的微小变化不敏感，甚至能从中受益。





## 理论

### 5. XGrammar：高效、严格的结构化生成约束 {#xgrammar}

- **用途 / 问题**：让模型生成 JSON、XML、代码等递归结构时满足完整 CFG 约束，同时避免逐 token 遍历整个词表造成高延迟；XGrammar 已作为 vLLM 的结构化生成后端之一。
- **关键结论**：XGrammar 将 CFG 转为**字节级 PDA**，对绝大多数上下文无关 token 预计算并缓存合法性，再通过上下文扩展、持久化执行栈与 PDA 优化降低动态校验量，并让 CPU mask 计算与 GPU 推理重叠。
- **工程价值**：适用于函数调用参数、配置生成和协议输出，可把格式保障前移到解码过程，减少解析失败、重试和事后修复。
- **限制 / 核验动作**：语法正确不等于字段语义正确或业务约束满足。需在目标模型、词表、语法复杂度、batch 和硬件上复测吞吐、首 token/逐 token 延迟与缓存内存，并增加 schema 语义校验；“100%”及加速比例应回到论文实验设置核验。

[论文：*XGrammar: Flexible and Efficient Structured Generation Engine for Large Language Models*](https://arxiv.org/pdf/2411.15100)

| 核心机制 | 核心作用 | 具体实现方式 | 优势（对比传统方法） |
| --- | --- | --- | --- |
| 基于字节级下推自动机（PDA）的 CFG 解析 | 精准支持复杂递归格式（JSON/XML/代码），处理不规则 token 边界 | 1. 将 CFG 转换为字节级 PDA，每个字符边支持一个或多个字节；<br>2. 用栈管理嵌套结构；<br>3. 兼容跨 token 的语法元素 | 传统正则无法支持递归结构，普通 PDA 难以处理 token 边界错位，字节级 PDA 可覆盖复杂格式规则 |
| 自适应令牌掩码缓存 | 预计算绝大多数 token 的格式合法性，减少运行时校验开销 | 1. 上下文无关 token（占比超过 99%）预计算合法/非法结果，并以“栈顶节点”为键缓存；上下文相关 token（不足 1%）运行时校验；<br>2. 根据“接受密集/拒绝密集”自适应选择存储方式 | 传统方法需遍历全部词表实时校验；缓存机制将校验速度提升 100 倍，内存占用降至 0.2% |
| 上下文扩展优化 | 进一步减少上下文相关 token 数量 | 1. 为每个语法规则预计算“扩展后缀”；<br>2. 过滤不符合父规则扩展后缀的 token | 可减少 90% 的上下文相关 token，例如 JSON 语法从 1134 个降至 120 个 |
| 持久化执行栈 | 支持并行栈分支与快速回滚 | 1. 将多个并行栈组织为树形结构并共享重复节点；<br>2. 支持常数时间回滚；<br>3. 语法歧义时只拆分对应分支 | 避免复制完整栈，将字符校验量减少 70% |
| 下推自动机结构优化 | 减少语法歧义和栈分支 | 1. 将短小片段规则内联到父规则；<br>2. 合并同标签出边节点和 epsilon 边连接节点 | 减少 PDA 节点、边和无效分支，继续提高 mask 生成速度 |
| CPU-GPU 计算重叠 | 消除格式校验的额外开销 | 1. GPU 生成 logits 时，CPU 并行计算 token mask；<br>2. 预填充与缓存构建重叠，解码与 mask 生成重叠；<br>3. 仅在采样阶段同步 | 使结构化生成速度接近无约束生成 |

#### 关键结论

以上机制形成“全链路格式保障”：

1. 从源头（CFG → PDA）确保格式规则无遗漏，覆盖递归、嵌套等复杂结构；

2. 通过“预计算 + 缓存”减少 99% 的实时校验量，避免传统方法的遍历开销；

3. 对少量需实时校验的 token，用高效栈结构和优化后的 PDA 快速处理；

4. 最后通过 CPU-GPU 并行消除整体开销，同时保证 100% 格式正确性。

传统方法因“规则覆盖不全（如正则不支持递归）、校验串行、歧义处理低效”，导致格式正确率仅 60%–80%，而 XGrammar 通过上述机制实现“无死角约束 + 高效执行”，最终达成 100% 语法正确的结构化输出。

### 6. mHC：流形约束超连接 {#mhc}

- **用途 / 问题**：HC 通过解耦残差流宽度与计算层宽度，在不显著增加 FLOPs 的情况下增加连接拓扑和表达能力，但自由学习的残差混合会破坏恒等映射假设，并带来数值不稳定与系统开销。
- **关键结论**：mHC 不再让残差变换 $H^{\mathrm{res}}$ 完全自由学习，而是将其约束到能保持稳定性的流形；笔记给出的核心操作是投影到 **Birkhoff 多面体**。
- **工程价值**：为扩大残差通路宽度提供“表达能力—训练稳定性—计算成本”的折中思路，适合评估深层或大规模训练中能否比普通 HC 更稳定地获得额外容量。
- **限制 / 核验动作**：当前材料没有转录投影算法、稳定性定理、额外通信/显存成本和实验数值。应核对约束实现、是否严格保持双随机性质、收敛与规模化结果，并在相同参数量、FLOPs 和训练预算下与标准残差及 HC 对照。

核心思想：**与其让 $H^{\mathrm{res}}$ 自由学习，不如将其约束在一个能保证数值稳定性的特定流形上。**

**投影到 Birkhoff 多面体**

对 $n \times n$ 的连接矩阵，Birkhoff 多面体可写为双随机矩阵集合：

$$
\mathcal{B}_n = \left\{A \in \mathbb{R}_{\ge 0}^{n \times n}
\;\middle|\;
A\mathbf{1}=\mathbf{1},\; A^{\top}\mathbf{1}=\mathbf{1}\right\}.
$$

<ZoomableImage src="/paper-reading/assets/截屏2026-01-05%2014.20.02.png" alt="截屏2026-01-05 14.20.02.png" />
