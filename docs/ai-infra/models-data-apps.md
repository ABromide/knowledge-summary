# 模型、数据与应用

模型架构决定计算形态，数据决定模型看到的世界，应用系统决定能力如何被约束和验证。三者需要与 Infra 一起设计：架构变化会改变通信和缓存，数据流程会改变训练成本，应用目标会反向决定评估方式。

## 模型架构的三条演进线

1. **Transformer 内部优化**：从多头注意力到 MQA、GQA、MLA，主要在能力、KV Cache 与计算开销间权衡。
2. **稀疏化扩展**：MoE 用路由激活少量专家，在不同比例的参数量和计算量之间解耦，但引入负载均衡和专家通信问题。
3. **替代或混合架构**：RWKV、SSM/Mamba、RetNet 等尝试降低长序列复杂度；它们更可能与注意力形成混合系统，而不是简单“一代替一代”。

## 数据工程比“收集更多”更复杂

高质量数据管线至少包括来源管理、提取、格式化、安全过滤、去重、质量验证与版本追踪。预训练强调规模、覆盖与分布，后训练强调任务定义、反馈质量和边界样本。

一个可复用判断是：

> 数据质量通常比后训练数据数量更重要，但“质量”必须由目标任务、评估方法和可追溯来源共同定义。

合成数据可以扩展任务覆盖，却可能放大教师模型偏差；数据蒸馏能降低成本，却需要检查能力上限和分布坍缩。数据飞轮成立的前提是线上反馈真实、可用且不会把错误重新注入训练集。

## 多模态不是简单拼接模态

CLIP 建立跨模态对齐，DALL·E / Stable Diffusion 负责生成，BLIP 系列连接理解与生成。工程上需要明确每个模块的训练目标、表征接口和评估口径，否则“支持多模态”只会成为模糊标签。

## 应用层：Agent、RAG 与协议

- **Agent** 把模型置于规划、工具调用、环境反馈和状态管理的循环中。
- **RAG** 用检索补充动态或私域知识，价值在可更新、可引用和可控制，不只是让回答更长。
- **MCP / A2A** 分别关注模型连接工具与 Agent 间协作，但协议只能解决接口互操作，不能替代权限、安全与结果验证。

应用设计应先回答三个问题：模型何时需要外部信息、工具结果怎样验证、失败时系统如何回退。Qwen3 RAG、RAGFlow 等案例说明检索质量、切分、重排和引用仍是系统效果的关键。
