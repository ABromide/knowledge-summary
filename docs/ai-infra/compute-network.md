# 计算、通信与云原生

大模型集群的有效算力取决于最慢的那条链路。算力、通信、存储、供电散热和作业调度彼此耦合，万卡规模下任何局部不稳定都会被放大为整体效率损失。

## 计算集群：从芯片指标到有效算力

AI 服务器与传统通用服务器的差异，核心在于加速器密度、高速互连、内存带宽和供电散热。集群规模继续扩大后，关注点会从单卡峰值算力转向：

- 网络是否能支撑高频集合通信；
- 故障是否能被快速定位、隔离与恢复；
- 训练显存是否为参数、梯度、优化器状态和激活预留了真实空间；
- MFU 是否反映了通信、气泡和不均衡后的有效利用率。

万卡集群的主要挑战可以归为五类：电力与散热、网络通信、计算效率、系统可靠性、国产化与成本。规模越大，平均故障间隔越短，“无故障运行”不再现实，故障感知与弹性恢复必须进入训练系统设计。

## 通信：并行策略最终都会落到通信原语

| 并行方式 | 典型通信 | 主要压力 |
| --- | --- | --- |
| 数据并行 | AllReduce / ReduceScatter + AllGather | 梯度同步带宽 |
| 张量并行 | AllReduce / AllGather | 层内高频通信与低延迟 |
| 流水线并行 | Send / Recv | 阶段间激活传输与气泡 |
| 专家并行 | AllToAll | 流量不均与尾延迟 |

RDMA 绕过传统内核网络栈并减少数据拷贝，是大规模训练网络的基础。RoCEv2 在以太网上提供 RDMA，但要结合 PFC、ECN/DCQCN、合理拓扑与负载均衡处理拥塞；仅开启“无损”并不能自动消除 PFC 风暴、死锁和大象流问题。

NCCL / HCCL 等集合通信库负责把逻辑原语映射到实际互连拓扑。优化时应先确认 Scale-Up 与 Scale-Out 边界，再决定 Ring、Tree、分层集合通信或拓扑感知调度。

## 存储：Checkpoint 是训练稳定性的组成部分

Checkpoint 不只是备份文件。大模型训练中的保存、恢复和跨节点传输会占用大量带宽与停顿时间，需要在以下方案间权衡：

- 分片保存，避免集中写入；
- 异步或增量 Checkpoint，降低训练停顿；
- 计算节点本地缓存与并行文件系统配合；
- 明确模型状态、优化器状态与数据游标的完整性边界。

分布式文件系统的设计目标并非只有峰值吞吐，还包括元数据扩展、故障恢复、小文件行为与训练访问模式适配。

## 云原生：容器是隔离视图，Kubernetes 是控制循环

容器的本质是 Namespace 提供资源视图隔离、Cgroups 提供资源限制、OverlayFS 组织镜像层；它并不是轻量虚拟机。Kubernetes 在此基础上通过声明式 API 和控制器持续把实际状态拉回期望状态。

在 AI 集群中，重点不是“会写 Deployment”，而是：

1. 用 requests / limits 和 QoS 明确资源边界；
2. 让 GPU、拓扑、存储和网络约束进入调度；
3. 使用 CSI、CNI、CRI 分离存储、网络和运行时实现；
4. 用 Prometheus、日志与告警覆盖从节点到作业的三层指标；
5. 为长任务设计优先级、抢占、失败恢复与可观测性。

## 使用这组知识时先问

- 当前瓶颈是单节点算力、跨卡互连还是跨节点网络？
- 性能数据测的是峰值、端到端吞吐，还是故障后的长期均值？
- 存储与调度策略是否匹配训练任务的持续时间和恢复成本？
