# 训练与推理系统

训练追求稳定地完成大量并行计算，推理追求在动态请求下平衡延迟、吞吐和成本。两者共享模型与硬件，但工作负载并不相同，不能把训练优化原样搬到线上服务。

## 分布式训练：四种切分方式

| 策略 | 切分对象 | 适合解决 | 典型代价 |
| --- | --- | --- | --- |
| 数据并行 DP | batch | 吞吐扩展 | 梯度同步 |
| 张量并行 TP | 层内矩阵 | 单层放不下一张卡 | 高频集合通信 |
| 流水线并行 PP | 模型层 | 跨设备放置模型 | 气泡与调度复杂度 |
| 序列 / 上下文并行 SP/CP | token 序列 | 长上下文显存与计算 | 注意力通信与负载均衡 |

MoE 进一步通过专家并行获得“大参数量、稀疏激活”，代价是 AllToAll 通信和路由不均。实际训练通常组合多种并行方式，目标不是策略越多越好，而是在显存、通信、气泡与工程复杂度之间找到可运行点。

## 显存与计算优化

- **ZeRO** 分阶段切分优化器状态、梯度和参数，降低单卡冗余。
- **Flash Attention** 用分块与重计算减少 HBM 往返，是 I/O 感知优化而不只是公式改写。
- **混合精度** 用更低精度提升吞吐，但需要缩放、累加精度和数值稳定性保障。
- **流水线调度** 通过微批次和虚拟阶段减少气泡，但会增加通信和调度复杂度。

## 后训练：反馈信号决定可学到什么

SFT 适合注入明确示范；RLHF / PPO 用奖励模型优化偏好；DPO 把偏好优化转为更直接的对比目标；GRPO 通过组内相对奖励减少对独立价值模型的依赖。选择算法前应先确认：奖励是否可验证、是否足够稠密、训练是否会损伤已有能力。

低秩微调（LoRA 及变体）适合在有限资源下调整模型，但它解决的是参数更新成本，不会自动解决数据质量、评估或部署隔离问题。

## 推理：Prefill 与 Decode 是两种负载

Prefill 对输入 token 并行计算，通常更偏计算密集；Decode 每步生成一个 token，频繁读取权重与 KV Cache，更容易受到内存带宽和调度影响。长上下文与高并发下，两阶段的资源争用会更加明显。

### 关键技术对应的瓶颈

| 技术 | 主要解决 |
| --- | --- |
| KV Cache | 避免重复计算历史 token |
| PagedAttention | 降低 KV Cache 碎片并支持灵活调度 |
| Continuous Batching | 动态合并不同生命周期的请求 |
| Ring Attention / Ulysses | 扩展长序列并行 |
| 量化 | 降低权重与激活的存储、带宽成本 |
| 知识蒸馏 | 将大模型能力迁移到更小模型 |

## 评估不能只看一个数字

推理系统至少同时记录：首 token 延迟、逐 token 延迟、端到端延迟、吞吐、并发、显存占用和失败率。离线单请求最快的实现，在动态批处理或尾延迟约束下未必是线上最优。

训练评估也需要区分：新任务能力、原有能力保持、训练稳定性和真实成本。只有训练 loss 下降不能证明模型更可用。
