# 训练、推理与反馈

Agent 训练的目标，是让模型在环境中持续选择有效动作，而不只是模仿一段看起来合理的思维链。最难的部分通常是任务环境、反馈密度、训练与推理一致性，以及如何避免能力遗忘。

## 从基模到 Agentic 能力

一条典型能力链路包括：

1. 预训练建立语言、代码和知识底座；
2. 中期训练强化目标领域与长上下文；
3. SFT 教会格式、任务接口和基本行为；
4. Reasoning RL 优化可验证推理；
5. Agentic RL 训练多轮工具调用和环境交互；
6. 跨阶段蒸馏或稳定化机制减少后续训练对已有能力的破坏。

Agentic 数据合成也需要完整流水线：从真实 issue、终端操作或检索问题抽取种子任务，构造可执行环境，采集轨迹，用测试或规则验证，再转换为训练数据。缺少环境验证时，轨迹“看起来正确”并不足以训练可靠 Agent。

## 多轮任务的核心：信用分配

终局奖励只能说明整条轨迹是否成功，难以指出哪一步工具调用或推理真正有贡献。近期方法主要沿三条方向改进：

- **回合级归因**：在 MDP 中为每次响应或工具调用估计相对优势；
- **过程与结果混合奖励**：既看最终答案，也评价检索证据、步骤有效性或推理质量；
- **多智能体与反思**：让不同角色互评、修订，但必须控制协作成本与不稳定性。

稠密奖励不是越多越好。若过程评价可被投机，模型可能学会“刷步骤分”而不是完成任务，因此常用结果奖励做门控。

## On-policy distillation：把环境反馈变成 token 级信号

传统 RLVR 在整组采样都失败时，组内相对优势可能塌缩为零。Self-distillation 的思路是让同一个模型分饰 Student 和 Self-Teacher：Student 正常作答，Teacher 额外看到运行错误、失败测试或参考答案，再评价原轨迹中各 token 的概率。

这带来三点价值：

1. 信号从序列级变为 token / logit 级，更接近真实错误位置；
2. 环境报错与成功参考互补，能突破单一标量奖励的信息瓶颈；
3. 在线分布更贴近当前策略，较离线 SFT 更有机会保持原有通用能力。

但代价也真实存在：Teacher 前向、在线生成、EMA / trust region 稳定化和 Top-K logit 近似都会增加系统复杂度。原笔记记录的实验结论显示，信号越稠密通常效果越好，但这些结果仍需结合具体模型与任务验证。

## 难题探索：先进入“可学习区域”

当模型在难题上 pass@k 为零，直接 RL 无法获得非零奖励。POPE 一类方法使用专家解答的短前缀把模型引导到更可能成功的状态，再保持后续 rollout 为 on-policy。关键不在复制前缀，而在扩大有引导与无引导轨迹的状态重叠，让策略逐步学会从原始问题到达有效区域。

这个思路提醒我们：处理不可解任务时，应先改变探索分布，而不是只增加采样次数或把简单题混进来刷分。

## 工程检查清单

- 任务是否有真实可执行环境与确定的成功条件？
- rollout、训练框架和线上推理是否存在版本或采样不一致？
- 奖励能否区分“结果正确”和“过程有用”？
- 全失败样本是否仍能得到有效学习信号？
- 新能力提升时，原有通用能力是否被单独回归测试？
- 异步采样带来的 off-policy 偏差是否被监控？
