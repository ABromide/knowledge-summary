# 知识地图：先建立问题，再建立目录

知识地图不是学科目录的复制品，而是一组你会反复遇到的问题。好的地图能让新材料快速找到位置，也能暴露现有认知的空白。

## 从长期问题开始

先写下 3—5 个未来半年仍然重要的问题，例如：

- 怎样稳定地交付高质量产品？
- 怎样让团队决策有据可查？
- 怎样理解并应用生成式 AI？

## 用三层结构保持简单

```text
主题
├── 核心概念
├── 方法与工具
└── 案例与反例
```

当某个分支超过十篇内容，再考虑继续拆分。目录应当跟随内容生长，而不是提前设计到最细粒度。

## 每月做一次断舍离

删除失效链接，合并重复结论，把已经不再重要的主题移入归档。整理的目标不是保持“整齐”，而是维持检索和判断效率。
